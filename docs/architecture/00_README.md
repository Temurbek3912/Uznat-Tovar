**Долгосрочное видение (добавлено в 1.3).** «Узнать товар» — **универсальная платформа для розницы**: продукты, одежда и обувь,
электроника, цветы, бытовая химия и другие магазины. В будущем — десятки и сотни магазинов, сеть, сотни и тысячи пользователей,
ИИ-помощник для сотрудников. **Первая версия остаётся прежней:** один продуктовый магазин, локально, без облака. Архитектура
закладывает рост и не реализует его раньше времени. Как это отразилось на каждом документе — раздел «Универсальная платформа» в каждом
из них; сводка «оставить / изменить / дополнить» — документ 14, §2.4.

**Принятые решения владельца (2026-11-06):** D-07 — закреплённый локальный IP в QR (локальное имя исследовано и признано
ненадёжным для покупателей), фиксированный порт, только публичный вход; D-10 и D-10а — фото покупателей не сохраняются, кадр
для выбора товара — только в памяти до 2 минут; D-11 — RPO ≤ 24 ч, RTO ≤ 30 мин / 2–4 ч (подтвердить испытаниями); D-15 —
локальный Git; В-1…В-5 — структура документов, типы карточек, ориентиры нагрузки, цены, гостевая сеть. Новые архитектурные
решения 1.3 и уточнения 1.4 (каталог, ИИ, изоляция магазинов, варианты) — документ 14, §2.3. ИИ-помощник — **только текстовый чат**
на основе LLM, без голоса и синтеза речи (D-37). Решения не разрешают изменений кода, базы, конфигурации, сети или данных:
каждое внедрение — отдельным разрешением.

## Главные выводы (коротко)

1. **Распознавание ещё не проверено на реальных фото**, а эталонных фото на диске нет. Небольшой реальный benchmark
   (документ 07) — первый и самый важный шаг. Без него нельзя выбирать ни модели, ни пороги, ни роль детектора.
2. **Покупатель сейчас не может пользоваться распознаванием без входа:** `POST /api/v1/catalog/identify` требует токен.
   Для анонимных покупателей нужен отдельный публичный API с ограничением частоты запросов (документы 04 и 10).
3. **В проекте нет миграций базы** (`create_all`, Alembic не подключён). Любое расширение карточки, прав или истории
   начинается с базовой миграции Alembic (документы 02 и 14).
4. **Лицензия детектора — коммерческий риск.** Ultralytics YOLO11 распространяется под AGPL-3.0 или коммерческой лицензией.
   Ultralytics считает, что под AGPL подпадают и обученные модели. Нужна юридическая проверка до закрытого коммерческого дистрибутива (документ 07).
5. **Для Desktop backend должен работать в фоне независимо от окна.** Телефоны покупателей ходят на сервер, пока магазин открыт,
   даже если окно программы закрыто. Отсюда требования к выбору оболочки (документ 03).
6. **Redis и Celery остаются для Docker (разработка и сервер), но не переносятся в Desktop.** Для Desktop нужна надёжная
   очередь без Redis, кандидаты — в документе 08.
7. **Резервная копия сейчас — только база через Docker.** Фото и индекс не копируются, восстановление вручную и не проверяется (документ 09).
8. **Узбекская кириллица отсутствует:** в интерфейсе есть только узбекская латиница, в данных товара полей переводов нет вообще (документ 06).
9. **Универсальный каталог (1.3):** общие поля товара — обычные столбцы; характеристики категорий — справочник в таблицах
   (владелец редактирует без кода) + значения в JSONB строго по справочнику + узкая индексная таблица для фильтров (документ 06).
10. **Рост без переписывания (1.3):** первая версия — «узел магазина»; для сети — будущий «центр организации». Сейчас закладываются
    только дешёвые правила S-1…S-10 (документ 17, §3.2), сеть и облако не реализуются.
11. **ИИ-помощник (1.3, уточнён в 1.4)** — отдельная необязательная подсистема для владельца и сотрудников с разрешениями (режимы «чтение» и «действия», диалоговое заполнение базы через черновики): действия только через инструменты
    приложения с серверной проверкой прав, предпросмотром, подтверждением и аудитом; покупателям недоступен (документ 16).
12. **Роли и учётные записи (1.6):** вместо фиксированных ролей — роли из отдельных разрешений, которые владелец создаёт сам; шесть
    стартовых ролей как примеры; явный запрет сильнее разрешения; нельзя выдать больше, чем есть у себя, и управлять тем, кто сильнее; владелец —
    признак, а не роль, последнего владельца нельзя отключить. Сотрудников заводит владелец: временный пароль один раз, обязательная смена,
    блокировка и отзыв доступа действуют сразу (документ 05).
