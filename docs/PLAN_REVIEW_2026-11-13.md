# Сверка плана и архитектуры перед разработкой (2026-11-13)

**Что это.** Не аудит кода. Проверка того, насколько архитектура (`docs/architecture/`, версия 1.11 + документ 18) и планы
(`DEVELOPMENT_MASTER_PLAN.md` 1.12, документ 14, `ENGINEERING_STATUS.md` §7) годятся как основа для дальнейшей разработки, и
исправленный порядок работ. Этот документ **главный по порядку работ** с 2026-11-13; при расхождении с более старыми планами
действует он. Решения владельца, принятые ранее, не меняются.

## 1. Что в архитектуре хорошо и остаётся без изменений

- Принципы (документ 02, §1): один магазин, local-first, backend не переписывается, одна бизнес-логика на сервере, право системы
  на отказ от ответа, рост через «узел магазина» без преждевременной сети.
- Данные «по смыслу», без механического `store_id` (02, §5); гибридный каталог «столбцы + справочник + JSONB» (06, D-20).
- Распознавание: штрихкод — основной путь, вид — с честным отказом, пороги только по замеру (07).
- Вход и безопасность (05, 18): одна система входа, TOTP, сеансы, отдельный административный вход, только защищённый канал.
- Резервные копии с обязательной проверкой восстановления (09).
- ИИ-помощник — необязательный, только через сервисный слой с теми же правами (16).

Менять архитектурные решения не нужно. Проблемы — в **порядке работ, актуальности документов и долге схемы базы**.
