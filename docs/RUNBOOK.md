# RUNBOOK: с нуля до работающей системы
### Acer Predator Helios Neo 16S AI (Windows, RTX 5060 8GB)

Этот документ объединяет всё в один порядок действий. Детали по обучению
детектора и по узбекским языковым пакетам OCR — в отдельных файлах
(`training_guide.md`, разделы ТЗ), здесь — сжато со ссылками, чтобы не
дублировать по три раза.

> **Всё в Docker, без Python на компьютере?** Это отдельный сценарий — `docs/DOCKER.md` (`docker compose build` →
> `docker compose up -d`: таблицы, папки и первый администратор создаются сами). Ниже — запуск API и воркера на хосте
> (с прямым доступом к GPU).

> **Обновлено 2026-11-06.** Разделы про аудит полок (магазины, планограммы, камеры, дашборд, ручная проверка, отчёты) убраны вместе с кодом;
> остались установка, запуск, каталог и распознавание. Состояние работ — `docs/CLEANUP_STATUS.md`.

**Что вы получите в конце**: API + Celery-воркер, работающие на вашей
машине (с доступом к вашей GPU), Postgres+Redis в Docker, страницу «Узнать товар» в браузере.
Важно — **это заработает даже без обученной модели** (см. пункт 5) и даже
без единого реального SKU в каталоге (см. пункт 6.3) — система изначально
спроектирована деградировать предсказуемо, а не падать.

## 1. Что установить (один раз)

| Что | Зачем | Где взять |
|---|---|---|
| Docker Desktop | Postgres + Redis (инфраструктура, не GPU) | docker.com, при установке включить WSL2-backend |
| Python 3.14 | Всё остальное | python.org, отметить "Add to PATH" |
| Tesseract OCR + языки | F11, OCR ценников | github.com/UB-Mannheim/tesseract/wiki — офиц. Windows-сборка |

**Про Tesseract отдельно**: при установке инсталлятор UB-Mannheim спросит,
какие доп. языки поставить — отметьте **Uzbek**, **Uzbek (Cyrillic)** и
**Russian** (English ставится по умолчанию всегда). После установки добавьте
`C:\Program Files\Tesseract-OCR` в переменную PATH (инсталлятор обычно
предлагает это сделать сам — соглашайтесь). Проверка:

```powershell
tesseract --list-langs
```

Должны увидеть `eng`, `rus`, `uzb`, `uzb_cyrl` в списке. Если каких-то не
хватает — переустановите Tesseract и на этот раз отметьте галочки для них
(доп. языки можно доустановить, повторно запустив тот же инсталлятор).

## 2. Распаковать проект и поставить зависимости

```powershell
# распакуйте retail-shelf-audit.zip, затем:
cd retail-shelf-audit
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
```

**Сначала PyTorch с поддержкой вашей GPU** (иначе следующий шаг поставит
случайную версию torch без Blackwell-поддержки — см. `training_guide.md`,

```powershell

python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

Дальше — весь остальной проект одной командой (torch уже установлен нужной
версии, pip его не тронет):

```powershell
pip install -r requirements.txt
copy .env.example .env
```

Это займёт время — тянутся torch/transformers/faiss, несколько ГБ.

## 5а. Проверка окружения перед запуском (preflight)

Прежде чем запускать API и воркер, прогоните проверку — за пару секунд она покажет, чего не хватает:

```powershell
python -m scripts.preflight
```
Она проверяет: версию Python, установленные пакеты, настройки, **видеокарту и сборку PyTorch** (RTX 5060 = Blackwell
требует PyTorch с `cu128`, иначе ошибка проявится только при первом вычислении), Tesseract и языки, веса детектора и
эмбеддера, доступность Postgres и Redis, таблицы, администратора, магазины, каталог, запись в папку фото и место на диске.
`[FAIL]` — блокирует запуск (в подсказке под строкой — что сделать); `[WARN]` — запуск возможен, но с ограничением
(например, без весов YOLO будет грубая эвристика). Ничего в БД не изменяет. Код возврата 1 при любом `[FAIL]`.

## 5б. Детектор товаров на ваших фото

Без обученных весов работает запасная эвристика, годная только для простого макета (коробки на светлом фоне с зазорами). Видит ли ваш
обученный детектор товар на ваших фото, проверяет `python -m ml.probe_detector --photos data/probe --out data/probe_out` (в Docker:
`docker compose run --rm --no-deps api python -m ml.probe_detector --photos data/probe --out data/probe_out`; фото — в `data\probe`,
результаты — таблица, `report.csv` и фото с рамками в `data\probe_out`). Чтобы обучить детектор на своих фото — `docs/detector_quickstart.md` (съёмка -> черновая разметка -> правка -> обучение -> оценка;
команды `python -m ml.detector_kit preannotate|split|check|train|evaluate`).

## 6. Запуск приложения

Два отдельных терминала, в обоих — активированный venv (`.venv\Scripts\activate`).

**Терминал A — API:**
```powershell
uvicorn app.main:app --reload --port 8000
```

**Терминал B — Celery-воркер.** На Windows нативно у Celery есть известное
ограничение (не поддерживается multiprocessing-пул `prefork`, завязанный на
`fork()`, которого в Windows нет) — обязательно флаг `--pool=solo`:
```powershell
celery -A app.worker.celery_app worker --loglevel=info --pool=solo
```
Если и это будет капризничать — надёжнее запустить воркер внутри WSL2
(Ubuntu), пока API остаётся на Windows; дайте знать, распишу отдельно.

### 6.1 Проверка, что API живой
```powershell
curl http://localhost:8000/health
```
Ожидаем `{"status":"ok","environment":"development"}`. Это единственный эндпоинт
(кроме логина), доступный без токена.

### 6.1а Войти и получить токен (F13)
```powershell
curl.exe -X POST http://localhost:8000/api/v1/auth/login -d "username=admin&password=<ваш_пароль>"
```
В ответе поле `access_token`. Дальше во всех запросах — заголовок
`-H "Authorization: Bearer <access_token>"` (в PowerShell используйте `curl.exe`,
а не алиас `curl`). Проще всего для ручных проверок — Swagger UI:
`http://localhost:8000/docs` → кнопка **Authorize** → логин/пароль, и все
запросы из браузера пойдут уже с токеном. Токен живёт 12 часов (`auth.token_ttl_minutes`).

Если 5 раз подряд ввести неверный пароль, вход отвечает `429 Too Many Requests` на
15 минут (`Retry-After` в ответе) — даже с правильным паролем. Это защита от подбора, а не
поломка. Во время локальной отладки блокировка снимается перезапуском `uvicorn`
(счётчик хранится в памяти процесса).

### 6.3 Почему всё будет "unknown" — и как добавить первый реально распознаваемый товар

Без единого эмбеддинга в индексе матчер честно не может узнать НИЧЕГО —
каждая детекция получит статус `unknown`. Это ожидаемо, а не ошибка. Чтобы
увидеть `matched`, добавьте хотя бы один товар с реальными эталонными фото
(сфотографируйте любой предмет с телефона 2-3 раза с разных ракурсов):

```powershell
python -m scripts.add_product_from_local_file --sku TEST-001 --name "Тестовый товар" --brand DemoBrand --category Тест --price 99.90 --photo C:\путь\фото1.jpg --photo C:\путь\фото2.jpg
```

При первом запуске скачает публичную модель `facebook/dinov2-base` (нужен интернет, разово, ~350 МБ),
потому что дообученных весов (`models/embedder/dinov2_base_retail_ft`) у вас пока нет. Если позже подключите свои
веса — **пересоберите индекс каталога**: эмбеддинги разных моделей несовместимы. Если эмбеддер не загрузился
(например, нет интернета), воркер теперь остановится с понятной ошибкой, а не будет молча работать на случайных
векторах; для отладки без весов можно явно задать `ALLOW_DEBUG_EMBEDDER=1` (результаты сопоставления бессмысленны). После этого сфотографируйте тот же предмет ещё раз в другом
ракурсе и покажите его на странице «Узнать товар» (`/ui/identify.html`) — теперь
система должна узнать его (статус `matched`).

**Много товаров сразу.** Для каталога из десятков и сотен SKU не заводите товары по одному: положите фото в папки `catalog/<артикул>/*.jpg`
(+ `products.csv`), проверьте `python -m scripts.import_catalog --dir catalog --validate-only` (без базы и видеокарты) и загрузите
`python -m scripts.import_catalog --dir catalog`. Повторный запуск безопасен, новые фото к существующему товару добавляются, отчёт покажет
похожие товары. Подробно — `docs/catalog_guide.md`; план пилота и подбор порогов по реальным фото — `docs/pilot_plan.md`.

## 6.5 Телефон: съёмка по Wi-Fi (без кабеля) и иконка на главном экране

Приложение для телефона — это веб-приложение (PWA): та же страница, но её можно добавить на главный экран, и она запускается с
иконки. Устанавливать ничего из магазина не нужно, кабель не нужен. Телефон и ноутбук должны быть в **одной Wi-Fi сети**.

1. Запустите API так, чтобы он слушал сеть, а не только localhost:
   ```powershell
   uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
2. Разрешите входящие на порт 8000 в брандмауэре Windows (PowerShell от администратора):
   ```powershell
   netsh advfirewall firewall add rule name="Shelf Audit API" dir=in action=allow protocol=TCP localport=8000 profile=private
   ```
3. Покажите адрес и QR-код (сам определит IP ноутбука; QR — если `pip install qrcode`):
   ```powershell
   python -m scripts.phone_url
   ```
   Наведите камеру телефона на QR-код или наберите адрес вручную: `http://<IP ноутбука>:8000` (корень сам откроет главную страницу).
4. Войдите, откройте «Узнать товар» и покажите товар камере телефона.
5. **Иконка на экран:** внизу страницы «Узнать товар» есть карточка «Иконка на экране телефона» с инструкцией под ваш телефон.
   - **iPhone (Safari):** «Поделиться» → «На экран «Домой»».
   - **Android (Chrome):** меню ⋮ → «Добавить на главный экран» (или «Установить приложение»).
   Иконка — стеллаж с товарами; подпись — «Узнать товар». После этого приложение запускается нажатием на иконку.

**Важно про `http://` и `https://`.** В локальной сети адрес начинается с `http://`. Иконка при этом создаётся (на iPhone —
и полноэкранный запуск), но **Android откроет её во вкладке браузера, а не на весь экран**, а кнопка «Установить»
(системное окно установки) и офлайн-режим появляются только при `https://`. Для курсовой этого достаточно. Если нужен полноэкранный
режим на Android и работа не только из одной Wi-Fi сети (например, телефон на мобильном интернете или в сети университета с
«изоляцией клиентов»):
- **Туннель с HTTPS** — например, Cloudflare Quick Tunnel: `cloudflared tunnel --url http://localhost:8000` выдаёт публичный адрес
  `https://….trycloudflare.com`, который открывается с любого телефона. По моим сведениям, так работает; я не проверял это в
  своей среде. **Осторожно:** API становится доступен из интернета — только на время демонстрации, с сильными паролями, без
  демо-пользователей, и закрыть туннель после показа.
- Приватная сеть Tailscale + HTTPS-сертификат — безопаснее, но настроек больше.

Ограничения: пароль идёт по `http://` открытым текстом (внутри вашей сети для пилота допустимо); при обрыве связи фото не
сохраняется в очередь — отправьте заново (офлайн-очередь потребует HTTPS и service worker — не реализовано); одно фото за раз.
Страница каталога открывается так же: `http://<IP>:8000/ui/products.html`.

## 6.7 Запуск одним щелчком и ярлык «Узнать товар» на рабочем столе

Чтобы не набирать команды (особенно на защите), всё запускается одним действием:

```powershell
python -m scripts.make_shortcut        # один раз: создаст на рабочем столе ярлык «Узнать товар» (только Windows)
```
Дальше — двойной щелчок по ярлыку (или по `start_demo.bat` в папке проекта). Окно покажет ход запуска и в конце — адрес и QR-код для телефона:

1. запускает Postgres и Redis через Docker (`docker compose up -d db redis`; если Docker не найден — считает, что они уже работают);
2. ждёт, пока Postgres и Redis начнут отвечать;
3. запускает API и воркер (воркер — в одном процессе: на Windows `--pool=solo`), журналы — в `logs\api.log` и `logs\worker.log`;
4. ждёт ответа `/health`, затем проверяет, что ни одна служба не упала сразу;
5. печатает адрес `http://<IP>:8000/ui/index.html` (главная) и QR-код (нужен `pip install qrcode`), открывает главную на этом компьютере.

**Остановка:** Ctrl+C в окне (или закрыть окно). Postgres и Redis при этом остаются запущенными (данные сохраняются); выключить — `docker compose stop`.
Если после закрытия окна порт 8000 остался занят, следующий запуск сам скажет об этом — закройте остатки процесса `python` в диспетчере задач или используйте `--port 8002` (8001 занят административным входом Docker, если он запущен).

Если служба упала, запускалка останавливает остальные и показывает последние строки её журнала. Параметры: `--check` (сначала
`scripts.preflight`), `--no-docker`, `--no-browser`, `--port N`, `--timeout S` (по умолчанию 90 с; **самый первый запуск** скачивает
модель эмбеддера и бывает долгим — запустите заранее или с `--timeout 300`).

**Не проверено в среде разработки:** работа `start_demo.bat`, создание ярлыка (PowerShell) и поведение при закрытии окна — это Windows;
оркестрация (порядок, сбои, остановка, настоящие подпроцессы, ожидание `/health`) проверена тестами на Linux. Прогоните запуск на
вашем ноутбуке заранее, не в день защиты.

## 6.8 Назвать любой товар: название товара не из базы по фото (без LM Studio)

Модель «зрение + текст» (Qwen3-VL-4B) запускает сама программа, отдельных программ не нужно (`scripts/vision_engine.py`).

* **Где лежит:** `models\vision` — движок llama.cpp (`llama-b12022\llama-server.exe`, сборка Vulkan: видеокарты NVIDIA, AMD,
  Intel, без CUDA) и два файла модели (2,5 ГБ + 0,8 ГБ). Ставит «Установить.bat» (и доставляет «Обновить.bat») только на
  компьютере с видеокартой NVIDIA от 6 ГБ и памятью от 12 ГБ. Вручную: `.venv\Scripts\python.exe -m scripts.vision_engine`;
  проверить: `... -m scripts.vision_engine --check`. Есть эти файлы от LM Studio — копируются оттуда, без интернета.
* **Как работает:** `start_demo` (оба режима) запускает движок рядом с программой на свободном порту только на 127.0.0.1,
  на видеокарте NVIDIA (на ноутбуке встроенная Intel пропускается), и передаёт программе адрес (`NAMING_VISION_URL`).
  Журнал — `logs\vision.log`. Закрывается вместе с программой, даже если она упала. Первый ответ — после загрузки модели
  (около 4–10 с), дальше около 1 с на фото на RTX 5060; видеопамяти — около 4,4 ГБ (вместе с программой — 5,4 ГБ).
* **Если движка нет** (`models\vision` не скачана) — по-старому используется LM Studio, если она стоит; нет и её — товар не из
  базы называется по штрихкоду, иначе только вид товара.
* **Мешает LM Studio:** если LM Studio держит в видеопамяти ту же модель, две копии не помещаются в 8 ГБ и ответ идёт
  около 10 с. LM Studio больше не нужна — закройте её или выгрузите модель (`lms unload --all`).

### Воркер не стартует или «не готов» (проверка после обновления OpenCV/детектора)

| Что видите | Что значит | Что делать |
|---|---|---|
| `docker compose ps`: воркер перезапускается; в `docker compose logs worker` — «Воркер не может стать готовым: OpenCV: …» | неисправный OpenCV (нет `CascadeClassifier`, версия 5.x, две сборки) | пересоберите образ без кэша: `docker compose build --no-cache api`, затем `docker compose up -d`; проверка: `docker compose exec worker python -m scripts.check_opencv` |
| …«файл весов детектора не найден: …sku110k_yolo11n.pt» | нет файла модели YOLO | положите файл в `models\detector\`; для временной демонстрации без него — `ALLOW_HEURISTIC_DETECTOR=1` в `.env` (качество низкое!) |
| воркер `unhealthy`, в логе таблица «Компоненты распознавания» со строкой `СБОЙ` | не поднялся обязательный компонент (причина в строке) | исправьте причину из строки; задачи распознавания до этого отклоняются с понятным сообщением, а не «успешно» |
| в таблице `ЗАМЁН` у детектора/эмбеддера | включён осознанный обход (`ALLOW_HEURISTIC_DETECTOR` / `ALLOW_DEBUG_EMBEDDER`) | результаты ненадёжны — для работы уберите флаг и почините причину |

### Если «Добавить товар» или «Узнать товар» не работают

| Что видите | Что значит | Что делать |
|---|---|---|
| «Очередь задач сейчас недоступна» | не запущен Redis | `docker compose ps`; `docker compose up -d redis` |
| «Это занимает дольше обычного…» и товар не появляется | не запущен или занят воркер (при первом запуске он ещё скачивает модель) | `docker compose logs --tail 50 worker`; подождите 1–2 минуты; `docker compose up -d worker` |
| «Система не успела ответить» на «Узнать товар» | то же: воркер не отвечает | то же |
| «Учебный режим … названия случайные» | вместо настоящей модели работает заглушка (`ALLOW_DEBUG_EMBEDDER=1`) | уберите флаг в `.env`, перезапустите воркер; нужен интернет при первом запуске |
| «Камера в браузере работает только на этом компьютере (localhost) или по HTTPS» | браузер не даёт камеру на обычном адресе в сети | на компьютере откройте `http://localhost:8000`; на телефоне — кнопка «Снять или выбрать фото» |
| Штрих-код не читается | код мелкий, не в фокусе, блестит или это не EAN-13/EAN-8/UPC-A | поднесите ближе (треть ширины кадра), держите ровно, уберите блик; иначе — распознавание по виду |
| «Штрих-код прочитан, но такого товара нет» | код ещё не привязан | «Добавить товар с этим штрих-кодом» или «Изменить» у нужного товара → штрих-код |
| «Контрольная цифра не сходится» | опечатка в ручном вводе | сверьте цифры с упаковкой |
| Товар добавлен, но «Не знаю» на его фото | мало фото или фото не похожи на то, что видит камера | «＋ Фото»: добавьте 3–5 ракурсов; см. `docs/catalog_guide.md` |

## 8. Порядок действий одним списком (TL;DR)

1. Поставить Docker Desktop, Python 3.14, Tesseract (+ uzb/uzb_cyrl/rus)
2. `python -m venv .venv` → активировать → torch с cu128 → `pip install -r requirements.txt`
3. `docker compose up -d db redis`, затем **`python -m scripts.preflight`** — исправьте все `[FAIL]`
4. `python -m scripts.seed_catalog`, затем `python -m scripts.create_user --username admin --role admin`
5. (опционально сейчас) обучить детектор — `training_guide.md`, скопировать веса
6. Два терминала: `uvicorn app.main:app --reload` и `celery -A app.worker.celery_app worker --pool=solo`
7. Добавить хотя бы 1 реальный товар — страница `/ui/products.html` или `scripts/add_product_from_local_file.py`
8. Войти (`/auth/login` или Swagger `/docs` → Authorize), открыть `/ui/identify.html` и показать товар камере
9. Проверить, видит ли детектор товар на ваших фото — `python -m ml.probe_detector` (п. 5б)
10. Телефон — п. 6.5; запуск одним щелчком — п. 6.7
