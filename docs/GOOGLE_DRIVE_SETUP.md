# Разовая регистрация программы у Google (для продавца)

Это делает **продавец программы один раз** — не магазины. Около 15 минут, бесплатно, банковская карта не нужна.
После этого в каждой копии программы в «Настройках» → «Резервная копия» работает кнопка **«Подключить Google Диск»**:
магазин открывает google.com/device (на компьютере или телефоне), вводит короткий код и входит в свой Google-аккаунт.
Больше магазину ничего ставить и настраивать не нужно.

Что программа получает от магазина: право **только на файлы, которые она сама создала** (папка «Узнать товар — копии»),
и адрес почты аккаунта — чтобы показать, к какому аккаунту подключено. Остальные файлы магазина программе не видны.

Сверено с документацией Google 2026-11-16 (вход по коду: developers.google.com/identity/protocols/oauth2/limited-input-device).
Названия кнопок у Google иногда меняются — если что-то называется чуть иначе, ищите по смыслу.

## Шаг 1. Проект

1. Откройте **console.cloud.google.com** и войдите в Google-аккаунт **продавца** (не магазина). Лучше завести отдельный
   аккаунт для программы, например `uznat.tovar.app@gmail.com`.
2. Вверху — выбор проекта → **«Новый проект»** (New project). Название: `Uznat tovar`. Создать.

## Шаг 2. Включить Google Drive API

1. Меню слева → **APIs & Services** → **Library** (Библиотека).
2. В поиске: `Google Drive API` → открыть → **Enable** (Включить).

## Шаг 3. Как программа выглядит для магазина (Google Auth Platform)

Меню → **Google Auth Platform** (раньше называлось «OAuth consent screen»). Если просит — **Get started**.

1. **Branding** (Оформление): название приложения `Узнать товар`, почта поддержки — ваша почта, контактная почта
   разработчика — ваша почта. Логотип **не добавляйте**: с логотипом Google требует отдельную проверку.
2. **Audience** (Аудитория): тип пользователей — **External** (Внешние): магазины входят своими обычными аккаунтами.
3. **Data Access** (Доступ к данным) → **Add or remove scopes** → отметьте только:
   - `.../auth/drive.file` — «файлы Google Диска, созданные этим приложением»;
   - `openid` и `.../auth/userinfo.email` (почта).

   Больше ничего не добавляйте. Google сам показывает категорию права: у `drive.file` она **не «sensitive»
   (чувствительная) и не «restricted»** — поэтому платная и долгая проверка приложения не нужна. Если в списке рядом
   с каким-то правом написано sensitive/restricted — это лишнее право, уберите его.

## Шаг 4. Ключ программы (клиент)

1. **Google Auth Platform** → **Clients** (Клиенты) → **Create client** (Создать клиента).
2. Тип приложения: **TVs and Limited Input devices** (Телевизоры и устройства с ограниченным вводом). Это важно:
   с другим типом вход по коду не работает (Google ответит `invalid_client`).
3. Название: `Uznat tovar`. Создать.
4. В появившемся окне нажмите **Download JSON** (Скачать JSON). Если окно закрыли — откройте клиента в списке, там
   тоже есть скачивание.

## Шаг 5. Положить ключ в программу

Переименуйте скачанный файл (`client_secret_....json`) в **`google_client.json`** и положите в **папку программы** —
рядом с `scripts`, `app`, `Установить.bat` в той копии, из которой вы собираете архив для магазинов.
`python scripts/make_package.py` сам положит его в архив, и у всех новых магазинов кнопка заработает.

Другой способ (для знающих): в файл `.env` магазина две строки из этого JSON —

```
GOOGLE_CLIENT_ID=....apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=....
```

`google_client.json` не попадает в GitHub (он в `.gitignore`). Для такого типа клиента Google не считает его
настоящим секретом — он есть в каждой копии программы; доступ к Диску магазина даёт только вход самого магазина.

## Шаг 6. Опубликовать приложение (обязательно)

**Google Auth Platform** → **Audience** → **Publishing status: Testing** → кнопка **Publish app** (Опубликовать) →
подтвердить. Статус станет **In production**.

Почему это обязательно: пока приложение в режиме **Testing**,
- войти могут только адреса, вписанные вручную в «Test users»;
- Google выдаёт ключ доступа **на 7 дней** — через неделю копии перестанут уходить в облако, магазину придётся
  подключать заново.

Для приложения только с правами `drive.file`, `openid`, `email` проверка Google при публикации не требуется
(она нужна лишь для чувствительных прав и для логотипа). Если Google всё же покажет при публикации предложение пройти
проверку — для этих прав её можно не проходить.

## Шаг 7. Проверить

1. Запустите программу с `google_client.json` в папке.
2. «Настройки» → «Резервная копия» → **«Подключить Google Диск»** → откройте google.com/device, введите код, войдите
   **любым** Google-аккаунтом (не тем, что в «Test users», — так видно, что публикация сработала).
3. Через минуту в «Настройках»: «Google Диск подключён: …». На drive.google.com этого аккаунта появится папка
   «Узнать товар — копии».

Если на шаге входа Google пишет «Доступ заблокирован» / «app is in testing» — приложение не опубликовано (шаг 6).
Если `invalid_client` — у клиента не тот тип (шаг 4, создайте нового с типом TVs and Limited Input devices).

## Ограничения Google, о которых стоит знать

- Ключ магазина пропадает, если копии **полгода** не уходили в облако, или если магазин сам отозвал доступ
  (myaccount.google.com → Безопасность → Сторонние приложения). Тогда «Настройки» попросят подключить заново.
- На один Google-аккаунт — не больше 100 действующих подключений к одной программе (старые вытесняются). Для магазина
  это не ограничение.
- Место в облаке — бесплатные 15 ГБ аккаунта магазина. Фото хранятся один раз на все копии; хранятся последние 7 копий.
