# Камеры: IP-камеры, телефон, агент

Как устроено: **камеры заводятся в админ-панели** (`/ui/admin.html` → «Камеры») и хранятся в базе; адрес источника — только зашифрованным.
**Снимает их агент** (`scripts/camera_agent.py --managed`): он раз в ~10 секунд спрашивает у сервера список камер, снимает каждую по её расписанию,
выполняет команды «Снимок сейчас» и «Проверить» и сообщает серверу результат. **Статус камеры («онлайн», «ошибка», …) вычисляется только из этих
отчётов** — наличие камеры в настройках «онлайн» не делает. Если агент не запущен, админ-панель так и скажет, а команды подождут его запуска.

Сервер сам камеры не опрашивает (второго «конкурирующего» агента нет), поэтому для USB-камер агент запускается на том компьютере, где они подключены.

## 1. Один раз: ключ шифрования адресов камер

RTSP-адреса содержат логин и пароль камеры. В базе они хранятся зашифрованными (Fernet, пакет `cryptography`); открытый адрес получает только агент.
Ключа «по умолчанию» нет — без него камеру добавить нельзя (админ-панель покажет ошибку с этой инструкцией).

```powershell
docker compose exec api python -m scripts.generate_secret_key
# напечатает строку CAMERA_SECRET_KEY=... — вставьте её в файл .env, затем:
docker compose up -d
```

**Сохраните ключ отдельно от базы** (менеджер паролей). Потеряете или смените — адреса камер расшифровать нельзя, их придётся ввести заново. Ключ не публикуйте и `.env` в git не добавляйте.

## 2. Служебная учётка агента

Агент входит под отдельной учёткой роли `camera_agent`: она видит только камеры **своих** магазинов, может загружать снимки и больше ничего (отчёты, каталог, пользователей — нет).

```powershell
docker compose exec api python -m scripts.create_user --username camera-agent --role camera_agent --store-id <ИД магазина>
```
ИД магазина показан в админ-панели («Магазины и полки»). Несколько магазинов — несколько `--store-id` (или правка в разделе «Пользователи»).

## 3. Запуск агента

### Вариант А — в Docker (сетевые камеры: RTSP, HTTP, телефон по Wi-Fi)

```powershell
copy configs\agent.example.yaml configs\agent.yaml          # по умолчанию server_url: http://api:8000 — внутренняя сеть Docker
# в .env добавьте строку:  CAMERA_AGENT_PASSWORD=<пароль учётки camera-agent>
docker compose --profile agent up -d
docker compose logs -f agent
```
Обычный `docker compose up -d` агента **не запускает** (профиль `agent`). При неверном пароле агент выходит с кодом 2 и Docker пробует перезапустить его не более 3 раз
(иначе лимит неудачных входов заблокировал бы учётку). **USB-камеры ноутбука из контейнера Docker Desktop на Windows недоступны** — для них вариант Б.

### Вариант Б — на хосте Windows (USB-камеры, или агент не на сервере)

Агент — отдельный скрипт, ему нужны только `opencv-python-headless`, `numpy`, `pyyaml`, `httpx`. Приложение в Docker от версии Python на хосте **не зависит**.
Для самых новых версий Python (3.13/3.14) готовых сборок opencv/numpy может не быть — **не проверялось**; безопасный выбор — отдельный Python 3.12 (системный удалять не нужно):

```powershell
py -3.12 -m venv .venv-agent
.venv-agent\Scripts\pip install opencv-python-headless numpy pyyaml httpx
$env:SHELF_AUDIT_PASSWORD = "<пароль camera-agent>"
.venv-agent\Scripts\python scripts\camera_agent.py --managed --config configs\agent.yaml
```
В `configs\agent.yaml` для хоста: `server_url: "http://localhost:8000"`. Агент на **другом** компьютере — только по HTTPS: в ответе сервера есть пароли камер, по открытому Wi-Fi это небезопасно.

**Автозапуск при старте Windows:** Планировщик заданий → «Создать задачу» → триггер «При входе в систему» → действие: программа `D:\retail-shelf-audit\.venv-agent\Scripts\python.exe`,
аргументы `scripts\camera_agent.py --managed --config configs\agent.yaml`, «Рабочая папка» — `D:\retail-shelf-audit`; пароль задайте системной переменной среды
`SHELF_AUDIT_PASSWORD` (Параметры → Система → О системе → Дополнительные параметры). *(Инструкция составлена по документации Windows; в этой среде не проверялась.)*

### Прежний режим (без админ-панели)
`python scripts/camera_agent.py --config configs/cameras.yaml` с перечнем камер в YAML работает как раньше (`configs/cameras.example.yaml`). Эти камеры в админ-панели не видны.

## 4. Добавить IP-камеру

1. В камере включите RTSP (в её веб-интерфейсе; у многих камер он выключен по умолчанию) и создайте отдельного пользователя для чтения потока.
2. **Путь потока угадывать не нужно и нельзя «на глаз»** — у каждого производителя он свой. Агент умеет подобрать его проверкой, ничего не записывая:
   ```powershell
   python scripts\camera_agent.py --probe 192.168.1.64 --user admin        # пароль спросит скрыто
   python scripts\camera_agent.py --discover 192.168.1.0/24                 # какие устройства в сети открывают порты камер
   ```
3. Админ-панель → «Камеры» → «+ Камера»: тип `RTSP`, адрес вида `rtsp://логин:пароль@192.168.1.64:554/<путь, найденный на шаге 2>`, магазин и полка, интервал (не меньше 30 с).
4. Кнопка **«Проверить»** — агент получит кадр и сообщит размер/причину ошибки (снимок на сервер не уходит). Затем **«Снимок сейчас»**, и в «Снимках» появится кадр.

ONVIF-автообнаружение и управление камерой по ONVIF **не реализованы** — система не ONVIF-менеджер. Облачные камеры без локального потока (Ezviz/Imou/Ring/Nest) не поддерживаются.

## 5. Телефон вместо камеры

### Вручную (рекомендуется): страница съёмки `/ui/capture.html`
Войти → магазин → полка → «📷 Сфотографировать полку» → предпросмотр → «Отправить» → статус обработки → результат. Работает на Android и iPhone **по обычному http** (кнопка открывает штатную камеру телефона).

«🎥 Снять камерой в браузере» — съёмка прямо на странице (выбор основной/фронтальной камеры, «Снять», «Переснять», отказ в разрешении объясняется). Браузер даёт камеру страницам **только по HTTPS или на localhost**;
`localhost` на телефоне — это сам телефон, а не ваш компьютер. По `http://192.168.x.x:8000` кнопка скрывается с пояснением.

**HTTPS для телефона в локальной сети** (вариант, который не открывает сервер в интернет):
- **Tailscale** (бесплатный личный план): установите на компьютер и телефон, включите HTTPS-сертификаты в консоли Tailscale и опубликуйте порт: `tailscale serve --bg 8000` — адрес вида `https://<имя>.<tailnet>.ts.net` с настоящим сертификатом, телефон доверяет ему без ручной установки.
- **Локальный центр сертификации (mkcert) + reverse proxy** (например Caddy) перед `api`: сертификат придётся установить в телефон вручную (корневой сертификат), для iPhone — ещё и включить доверие в настройках.
В проекте готового прокси-контейнера **нет**; приведённое — рекомендации, в этой среде не проверялись.

### Автоматически (периодические снимки): телефон как сетевая камера
Установите на **Android** приложение «IP Webcam» (или аналог), запустите сервер в приложении; в админ-панели тип `HTTP/MJPEG-поток`, адрес — тот, что показало приложение (`http://<IP телефона>:8080/video`; для одиночного кадра — `http_snapshot`).
Проверьте путь в браузере компьютера до добавления. Ограничения, о которых нужно знать:
- телефон должен быть на зарядке, экран/приложение активны — **при блокировке экрана Android усыпляет приложения**, съёмка прекращается (в приложении есть режим «не гасить экран» и фоновая работа — настройте и проверьте на своём телефоне);
- Wi-Fi должен быть стабилен; IP телефона лучше закрепить в роутере;
- **iPhone** как автоматическая сетевая камера надёжного решения без сторонних платных приложений не даёт; браузер iOS и Android **не умеет** снимать в фоне и при заблокированном экране — непрерывной съёмки из браузера не будет;
- постоянная съёмка полки — это, как правило, дешёвая стационарная IP-камера (RTSP), а не телефон.

## 6. Если что-то не работает

| Симптом | Что делать |
|---|---|
| При добавлении камеры «CAMERA_SECRET_KEY не задан» | раздел 1 |
| Все камеры «неизвестно», баннер «агент не подключался» | агент не запущен или не может войти: `docker compose logs agent` (вариант А) / консоль агента (Б); проверьте логин/пароль и роль `camera_agent` |
| Камера «ошибка: …» | текст причины в строке камеры и в «Журнале»; «Проверить» повторит попытку; пароль в сообщениях маскируется (`***`) |
| «Нет успешных снимков N мин» при работающем агенте | камера не отвечает; проверьте URL через `--probe`, питание, Wi-Fi; кадр может отвергаться как тёмный/размытый (событие «кадр непригоден») |
| «Проверить» зависло | команда ждёт агента; нет агента — нет выполнения (это видно по баннеру) |
| Диагностика базы | `docker compose exec api python -m scripts.diagnose` (только чтение) |

Не реализовано: live-видео в браузере (RTSP браузер напрямую не показывает; для первой версии — просмотр последних снимков и истории), ONVIF, серверная съёмка без агента.
