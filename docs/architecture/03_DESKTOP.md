# 03. Windows Desktop

## 1. Требования (утверждено)

Владелец устанавливает программу, запускает её с ярлыка и работает в окне: каталог, пользователи, история распознаваний,
резервные копии, настройки. Не нужны PowerShell, Python, Docker, ручной запуск серверов и установка библиотек.

## 2. Главное архитектурное наблюдение

**Backend должен работать, даже когда окно закрыто.** Покупатели сканируют QR и обращаются к серверу весь день.
Если сервер живёт внутри окна, то закрыл окно — и магазин остался без распознавания. Поэтому:

- **backend — фоновая служба** (служба Windows или процесс, который запускает супервизор при входе в систему);
- **окно — только клиент** этого backend: показывает интерфейс, состояние, управляет запуском и остановкой;
- значок в области уведомлений показывает состояние: «работает / запускается / ошибка» и даёт открыть окно или остановить сервер.

Это снижает ставки выбора оболочки: она не держит бизнес-логику, а только показывает существующий веб-интерфейс.

## 3. Сравнение вариантов оболочки

Цифры — порядок величины по общедоступным сравнениям. На наших условиях их нужно **измерить в прототипе**.
Важно: размер оболочки мал по сравнению с ML-частью (PyTorch с CUDA, модели), которая весит **гигабайты** в любом варианте.

| Критерий | **A. Tauri 2** | **B. Electron** | **C. pywebview** (окно из Python) | **D. Лаунчер + Edge в режиме приложения** |
|---|---|---|---|---|
| Что это | Rust-оболочка + системный WebView2 | Node.js + встроенный Chromium | Python-окно на системном WebView2 | Маленький exe/служба + `msedge --app=<адрес>` (окно без адресной строки) |
| Размер оболочки (оценка) | единицы МБ | порядка 80–150 МБ | единицы МБ (поверх Python) | меньше 1 МБ |
| RAM оболочки (оценка) | низкая (процессы WebView2) | выше (свой Chromium) | низкая | как у Edge |
| Связь с Python | процесс-«сайдкар» (`externalBin`) или служба + HTTP на localhost | дочерний процесс или служба + HTTP | **в том же процессе** или служба + HTTP | служба + HTTP |
| NVIDIA GPU | не касается (GPU нужен только backend) | не касается | если в одном процессе — нужна осторожность (окно и модели в одном процессе) | не касается |
| Запуск и остановка backend | плагин shell (сайдкары) или управление службой | `child_process` или служба | сам Python | служба Windows |
| Обновление | встроенный updater с подписью пакетов | electron-updater | своё | своё |
| Безопасность | модель разрешений Tauri (capabilities), маленькая поверхность | больше поверхность (Node в приложении, нужна аккуратная настройка) | WebView2 + Python | обычный браузер Edge, без доступа к системе |
| Удобство разработки | нужен Rust-тулчейн для сборки, логика остаётся в вебе | JS/Node, огромная экосистема | только Python | минимально |
| Сопровождение | средняя сложность | средняя | низкая | низкая |
| Известные риски | установщик NSIS может не заменить сайдкар при переустановке той же версии ([tauri#15134](https://github.com/tauri-apps/tauri/issues/15134)): решается версионированием и хуками установщика | размер, обновления Chromium | меньше готовых средств обновления и установки | выглядит «почти как приложение», ограниченная интеграция (уведомления, меню) |

Отклонено: **PySide6/Qt** (переписывание интерфейса, который уже есть на вебе) и **упаковка Docker Desktop в установщик**
(прямо противоречит требованию «без Docker»).

**Рекомендовано:** не выбирать оболочку заранее, а сделать **прототип A (Tauri 2) и D (Edge в режиме приложения)** на одном и том же
backend-службе. Tauri — основной кандидат: маленький, с подписанными обновлениями, с моделью разрешений. D — дешёвый
запасной вариант, если Tauri создаст трудности. Electron имеет смысл, только если в прототипе Tauri упрётся во что-то
конкретное (например, в WebView2 на целевых компьютерах).

## 4. Упаковка Python backend

| Вариант | Плюсы | Минусы |
|---|---|---|
| PyInstaller `--onefile` | один exe | при каждом запуске распаковывает гигабайты во временную папку — **медленный запуск**, не подходит для PyTorch |
| PyInstaller `--onedir` | обычная папка, быстрый запуск | анализ импортов иногда пропускает модули (transformers, ultralytics) — нужен тест на чистой Windows |
| **Встроенный Python** (embeddable zip с python.org) + готовая папка `site-packages` | предсказуемо, как в разработке; можно обновлять пакеты частями | нужно самим собрать папку зависимостей и проверить её |

**Рекомендовано:** `onedir` или встроенный Python; выбрать в прототипе по надёжности запуска на чистой Windows.

ML-часть:

- PyTorch с CUDA несёт свою CUDA-библиотеку; на компьютере нужен только **драйвер NVIDIA**. Видеокартам RTX 50-й серии нужны
  свежие сборки PyTorch с CUDA 12.8 или новее (**проверить** точную минимальную версию для выбранной сборки).
- **Два варианта пакета или докачка:** GPU-пакет (гигабайты) и CPU-пакет (заметно меньше). Предложение — общий установщик
  с CPU-пакетом и отдельный «пакет ускорения GPU». Решить после замера размеров.
- **Модели входят в установку.** Сейчас без дообученных весов DINOv2 скачивается из интернета при первом запуске
  (`app/pipeline/embedder.py`). В Desktop веса лежат в папке программы, HuggingFace переводится в офлайн-режим
  (переменная `HF_HUB_OFFLINE=1`), скачивание во время работы запрещено.

## 5. База данных в Desktop (решение D-02 не принято; сравнение уточнено 2026-11-07)

Серверный прототип (Docker) остаётся на PostgreSQL — это утверждено (документ 14, §2.1, п. 6). Для Windows Desktop база **не выбрана**:
сначала сравнение и прототип. Сейчас ничего не меняется, переход на SQLite не выполняется.

| Критерий | **PostgreSQL в составе установки** (служба на `127.0.0.1`) | **SQLite** (файл, режим WAL) |
|---|---|---|
| Совместимость с текущим кодом | полная (так работает сейчас) | высокая для простых запросов: тесты проекта уже идут на SQLite; PostgreSQL-специфика — advisory-замок в `bootstrap.py`, `pg_dump` в копиях |
| Совместимость с архитектурой 1.11 | всё как описано: JSONB и GIN для характеристик, диапазоны, блокировки строк для атомарного применения (документ 05, §13.1), частичные индексы | нет JSONB и GIN (есть JSON-функции), нет диапазонных типов (две колонки), нет блокировок строк — вся база блокируется на запись (атомарность сохраняется, механизм другой), нет рекомендательных блокировок; поиск без учёта регистра для кириллицы — через FTS5 |
| Установка | бинарники PostgreSQL (лицензия PostgreSQL License, разрешительная), `initdb` в папку данных, служба, порт, пароль — делает установщик; больше точек отказа (порт занят, антивирус, служба не стартовала) | ничего: библиотека входит в Python |
| Обновление программы | обычно без изменений базы; **смена основной версии PostgreSQL** — `pg_upgrade` или выгрузка и загрузка (можно держать одну основную версию на весь срок её поддержки) | миграции схемы как у любой базы |
| Надёжность при сбое | WAL и восстановление; на Windows нужны настройки сброса (документ 05, §13.3.5) | WAL; при `synchronous=FULL` устойчива к сбоям; те же ограничения диска и Windows |
| Параллельная запись | без ограничений | **один писатель**: для магазина достаточно, но длинный атомарный импорт задерживает другие записи на своё время |
| Резервная копия | `pg_dump` (проверенный путь в проекте) | встроенный API резервного копирования или `VACUUM INTO`; копия файла — только при остановке |
| Обслуживание обычным пользователем | служба скрыта установщиком, но может не запуститься | практически не требуется |
| Размер установки | около сотни МБ и больше (**оценка**) | дополнительно — ноль |
| Будущий сервер или центр сети | тот же диалект | два диалекта для тестирования и части кода |

Отклонены: SQL Server Express (тяжёлый, другой диалект, ограничения бесплатной версии), DuckDB (аналитическая, не для параллельной записи),
Firebird (мало опыта и инструментов).

**Как выбрать — испытания прототипа, одинаковые для обоих вариантов:** тихая установка и удаление на чистой Windows 10 и 11; обновление
программы без потери данных; 50 отключений питания во время записи (П-БД); создание и восстановление копии обычным пользователем через
интерфейс; атомарный импорт 20 тыс. строк одновременно с распознаванием и правками; время холодного запуска; размер установщика.

**Рекомендация (не решение):** склоняюсь к PostgreSQL — один диалект с серверным прототипом и архитектурой, меньше риск ошибок в двух
вариантах кода. SQLite — сильный вариант, если прототип покажет проблемы установки, обновления или обслуживания PostgreSQL у обычного
пользователя. До решения D-02 новый код фундамента не должен без необходимости опираться на возможности, которых нет в SQLite
(генеральный план, §6).

## 6. Обновление и удаление

- Данные лежат отдельно от программы (`%ProgramData%\UznatTovar\Data`, документ 02). Удаление программы данные **не удаляет**.
- Порядок обновления: проверка подписи пакета → резервная копия → остановка службы → замена программы → миграции Alembic →
  запуск → проверка `/health/ready` (включая ML) → только после этого «готово». При сбое: откат программы и, если миграция
  необратима, восстановление из копии, сделанной в начале обновления.
- Обновление программы (десятки МБ) и обновление ML-пакета (гигабайты) — **разные** операции с разной частотой.
- Подпись кода: неподписанный установщик вызывает предупреждение SmartScreen. Сертификат подписи кода платный —
  **требует решения** владельца ближе к коммерческому выпуску.

## 7. Прототип (до масштабной переработки)

Цель — проверить запуск и взаимодействие с backend на настоящей Windows, а не переписывать проект.

**Объём прототипа:**

1. Backend как фоновая служба: FastAPI + загрузка DINOv2 + `/health/ready`; данные в `%ProgramData%\…\Data`.
2. Локальный PostgreSQL: `initdb`, запуск, подключение, создание схемы (на копии, без данных магазина).
3. Окно A (Tauri 2) и окно D (Edge `--app`) открывают существующий интерфейс с backend; значок в трее показывает состояние.
4. Телефон в той же сети открывает страницу «Узнать товар» по адресу компьютера и отправляет фото (через `<input capture>`).
5. Установщик (для A) на **чистой** виртуальной Windows 10/11 без Python и Docker.

**Что измерить и записать в отчёт прототипа:**

| Показатель | Как | Ориентир (уточнить) |
|---|---|---|
| Размер установщика (CPU и GPU) | файл | — (записать факт) |
| Холодный запуск до «готово» (с загрузкой моделей) | секундомер, лог | до 60 с |
| Первое распознавание после запуска | лог | до 3 с на GPU |
| RAM / VRAM в покое и при распознавании | Диспетчер задач, `nvidia-smi` | записать факт |
| Закрыли окно — сервер работает | телефон продолжает распознавать | обязательно |
| Принудительное завершение backend — служба перезапускается | диспетчер задач | обязательно |
| Установка поверх той же и новой версии без потери данных | повторная установка | обязательно |
| Удаление программы оставляет `Data` | проверка папки | обязательно |
| Без NVIDIA или без драйвера — понятное сообщение и CPU-режим | ВМ без GPU | обязательно |
| Служба работает от учётной записи с минимальными правами (не `LocalSystem`) (1.11) | свойства службы | обязательно |
| Секрет доверенного устройства (DPAPI в области пользователя, документ 05, §12.12.1): переживает перезапуск окна, службы и Windows; не читается под другим пользователем Windows; поведение после смены пароля пользователем и после принудительного сброса администратором | испытание на чистой Windows | записать факт |
| Надёжность записи при отключении питания: П-БД, П-ФОТО, П-ДИСК (документ 05, §13.3.5) | реальный компьютер с отключением питания | обязательно перед коммерческим использованием |

**Критерий успеха:** все «обязательно» выполнены хотя бы в одном варианте, а цифры записаны. По ним принимается решение
об оболочке, базе (PostgreSQL или SQLite) и упаковке Python (документ 14, D-01…D-03).

## 8. Универсальная платформа: влияние на Desktop (добавлено в 1.3)

- **Desktop = узел магазина** (документ 17). Решение о фоновой службе backend (§2) становится ещё важнее: узел работает весь день
  для покупателей, сотрудников и, в будущем, синхронизации с центром.
- **ИИ-помощник — необязательный компонент, только текстовый чат.** Моделей речи (распознавание голоса, синтез речи) нет и не будет. Языковая модель (LLM) в установщик первой версии **не входит**: установщик и так весит
  гигабайты из-за PyTorch и моделей распознавания. Помощник подключается к внешнему локальному серверу моделей с OpenAI-совместимым API
  (например, LM Studio или Ollama) или к облаку по решению владельца (документ 16, §10). Без него программа работает полностью.
- **Видеопамять:** на 8 ГБ языковая модель и модели распознавания конкурируют. Проверить в прототипе (испытание Т-9, документ 17).
- **Несколько магазинов в одном окне** (переключатель магазина) — не в первой версии. Окно уже является клиентом API, поэтому позже
  это добавляется без изменения оболочки.
- **Учётная запись службы и секреты (1.11):** служба backend работает от учётной записи с минимальными правами; секрет доверенного устройства
  хранит **окно программы** в профиле пользователя Windows (DPAPI), служба его не расшифровывает и хранит только хеш; собственные секреты службы —
  в `%ProgramData%` с правами NTFS только для службы и администраторов (документ 05, §12.12.1). Программа удаления не удаляет данные и секрет устройства.
- **Схемы категорий и шаблоны** поставляются как данные установки. Обновление программы не перезаписывает изменённые владельцем категории.
