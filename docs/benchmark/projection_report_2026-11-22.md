# Точность после 2026-11-21 и что ещё помогает: замер 2026-11-22

Вопрос владельца: «насколько улучшилась точность и можно ли её ещё улучшить».

## Коротко, для владельца

1. **Что дал коммит 2026-11-21 (пороги 0,86 / 0,04, вопрос об объёме).** Верный товар первым — **по-прежнему 62,8 %**
   (в пятёрке — 76,1 %): порядок кандидатов тогда не менялся. Улучшилась **уверенность**: из ответов «найдено» неверных
   **30 вместо 93** (7 % вместо 20 %) при почти том же числе уверенных ответов (33 % против 35 %); товар не из базы
   «узнаётся» в 3,4 % случаев вместо 8,2 %. Объём по этикетке, когда модель ответила, — **61 верно из 62**. Перепроверено
   сегодня тем же замером (`ml/benchmark_similar.py`, 1290 снимков, 500 товаров) — цифры те же.
2. **Новое: лёгкая «проекция» поверх SigLIP 2.** Модель не меняется и ничего не скачивается: к её вектору добавляется
   поправка, обученная за полминуты на процессоре по уже посчитанным векторам каталога — чтобы разные фото одного товара
   (лицо, бок, состав) были ближе друг к другу. Честная проверка — на товарах, которых проекция при обучении **не видела**:
   верный товар первым **70,1 % вместо 62,8 %**, в пятёрке **86,4 % вместо 76,1 %**, на лицевых снимках 72,2 % вместо 66,5 %.
   Уверенных ошибок меньше (23 против 30), чужой товар принимается реже (3,1 % против 3,4 %), уверенных ответов почти
   столько же (32,0 % против 33,3 %). **Включена не сейчас:** нужна пересборка индекса (около минуты, фото не пересчитываются) и смена
   порогов — с согласия владельца.
3. **Исправлена ошибка:** «Сметана 15 %» и «Сметана 20 %» программа считала одним товаром разного объёма и могла по вопросу
   «какой объём» заменить верный ответ сметаной другой жирности (оба по 300 г). Теперь проценты — часть названия.
4. **Проверено и не помогло:** убрать из эталонов фото обратной стороны, состава и штрихкода (хуже на 4–11 пунктов: такие фото
   помогают); убрать фото, которые чаще всего «перехватывают» чужие снимки (−0,3…−1 пункт); шире круг для вопроса об объёме
   (у ошибок «другой объём» верный товар вообще не в первой пятёрке — круг ни при чём, дело в данных).
5. **Что даст своя съёмка.** У товаров с 1–2 фото в каталоге верный первым ~50 %, с 5 и больше — **71 %**; с проекцией на
   новых фото уже знакомых товаров — до 82 % (оценка с запасом: фото каталога одного товара часто сняты в один день). Своя
   лицевая фотография каждого товара, как снимает покупатель (`docs/benchmark_photo_guide.md`), — главный следующий шаг; и
   только она покажет настоящие цифры в магазине.

Всё измерено на фото каталога из интернета, **не на снимках магазина**.

## 1. Набор

Тот же, что 2026-11-21 (`ml/benchmark_similar.py`): каждое фото каталога — снимок, остальные — каталог; копии того же
товара (сходство > 0,93) убраны; 1290 снимков из 1741 вектора, 494 товара в распознавании (245 лицевых снимков). Решение
«найдено / похоже / не знаю» — `decide_match`, как в программе. Опыты — по копии векторов рабочего индекса
(`D:\uznat_tovar\accuracy-2026-11-22\exp`), индекс и база не менялись.

## 2. Проекция: как проверялось

`ml/train_projection.py`. Поправка y = norm(x + x·A), A — 768×768, контрастное обучение по парам фото (одного товара —
ближе), температура 0,05, 200 шагов, A тянется к нулю (weight_decay 0,01). Векторы — из кэша базы, без пересчёта фото.

Проверка: товары делятся на 5 частей; на трёх проекция учится, на четвёртой подбираются пороги (доли уверенных ошибок и
принятых чужих — на 10 % ниже нынешних), на пятой — замер; по кругу, каждая часть по разу — замер. Копии одного снимка
отбираются по векторам **без** проекции (иначе проекция, сближая фото, незаметно добавила бы копии в замер — первая версия
опыта этим ошибалась: 73,5 % вместо честных 69–70 %).

| | Верный первым | В пятёрке | Лицевые первым | «Найдено» | Неверно | Чужой принят |
|---|---|---|---|---|---|---|
| Без проекции (0,86 / 0,04) | 62,8 % | 76,1 % | 66,5 % | 33,3 % (429) | 30 | 3,4 % |
| С проекцией, те же пороги 0,86 / 0,04 | 70,1 % | 86,4 % | 72,2 % | 25,7 % (332) | 20 | 1,8 % |
| **С проекцией, пороги 0,83 / 0,08** | **70,1 %** | **86,4 %** | **72,2 %** | **32,0 % (413)** | **23** | **3,1 %** |

Устойчивость: обучение на трети товаров — 68–70 %; другие температуры и weight_decay (0,003–0,03; 0,05–0,1) — 69–71 %;
чем больше товаров в обучении, тем лучше. Новые фото уже знакомых товаров (деление по фото, 4/5 — обучение): 82,1 %, лицевые
91 % — оценка с запасом (фото одного товара в каталоге похожи друг на друга сильнее, чем снимок покупателя).

Проверено на настоящей модели: SigLIP 2 + проекция на видеокарте даёт ровно те же векторы, что проекция векторов из кэша
(косинус 1,0 на 10 фото); проекция применяется только к той модели, для которой обучена (паспорт в файле).

## 3. Что не помогло (цифры — верный первым, все снимки / снимки, похожие на лицевую сторону)

| Способ | Все | Похожие на лицевую (787) |
|---|---|---|
| Как есть | 62,8 % | 73,3 % |
| Убрать фото «не лицевая сторона» (SigLIP 2 по описаниям; 243–533 фото) | 51,6–58,0 % | 69,1–72,2 % |
| Убрать фото-«перехватчики» (≥ 2 чужих снимка, честно по половинам товаров) | −0,3…−1,0 пункта | — |

Данные базы: 25 товаров без лицевого фото в эталонах — у их снимков 59,8 % против 63,2 % у остальных (разница мала).
Ошибки «другой объём» — 10 из 1290, из них 9 — пары «с объёмом / без объёма» с разными штрихкодами (Alpen Gold Oreo,
Майонез Провансаль, кетчуп Heinz 320 / 350): у этих снимков верный товар даже не в пятёрке — поправить названия в карточках
(список — в отчёте `ml/benchmark_similar.py`).

## 4. Как включить проекцию (с согласия владельца) и как вернуть

1. `python -m ml.train_projection` — проверка и файл `models/projection/siglip2-base.npz` (отчёт рядом, `.md`).
2. `configs/config.yaml`: `models.embedder.projection_path: "models/projection/siglip2-base.npz"`, `match_threshold: 0.83`,
   `margin_threshold: 0.08`.
3. `python -m scripts.rebuild_index --apply --compute-missing` — векторы с проекцией берутся из кэша базы (без пересчёта фото),
   копия прежнего индекса — рядом. Новые фото товаров дальше считаются сразу с проекцией.

Вернуть: `projection_path: ""`, пороги 0,86 / 0,04, та же пересборка (векторы без проекции остались в кэше). Проекцию стоит
переобучать, когда товаров заметно прибавится (та же команда), и обязательно проверить на своих фото магазина.
