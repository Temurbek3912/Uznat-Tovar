# 13. Будущее облако и синхронизация

**Утверждено:** полноценную синхронизацию сейчас не реализовывать. Первая версия — один компьютер или сервер, один магазин.
Сложных Outbox/Inbox и межмагазинной синхронизации не делать.

## 1. Что заложить сейчас (дёшево и полезно уже в версии 1)

| Что | Где | Польза сейчас | Польза для облака |
|---|---|---|---|
| UUID-идентификаторы | уже во всех таблицах (`_uuid`) ✅ | — | записи с разных устройств не конфликтуют по ключам |
| `updated_at` | изменяемые таблицы каталога, пользователи, настройки | «изменено тогда-то» в интерфейсе | основа выбора изменений для отправки |
| `version` (целое) | товары, тексты, цены, пользователи и права | защита от одновременной правки (оптимистическая блокировка) | обнаружение конфликтов |
| Журнал действий `audit_events` | важные действия | безопасность и разбор ошибок | история изменений для разрешения конфликтов |
| Архивирование вместо удаления | товары | восстановление случайно удалённого | удаление можно передать как изменение статуса |
| Индекс как производные данные | манифест, кэш эмбеддингов | пересборка за секунды | индекс не синхронизируется, а пересобирается на месте |

Не делать сейчас: таблицы исходящих и входящих изменений, векторные часы, идентификаторы устройств и узлов,
серверную часть облака, механизм подписки, общий каталог сети.

## 2. Что понадобится, если облако появится (для справки)

- Режимы: только локально / вручную / автоматически по расписанию, кнопка «Синхронизировать сейчас».
- Очередь изменений при отсутствии сети, повторная отправка после восстановления.
- Безопасные повторы: каждое изменение с идентификатором, повторная доставка не применяется дважды.
- Версии записей и обнаружение конфликтов.
- Выбор, что синхронизировать (товары, тексты, фото, цены, пользователи — по отдельности).
- Настраиваемые уведомления. Когда облако выключено, никаких тревог о «несинхронизированных данных».
- Облако **не заменяет** резервные копии: синхронизация передаст и случайное удаление.

## 3. Политика конфликтов по типам данных (заранее, чтобы не выбрать по умолчанию «кто последний, тот прав»)

| Данные | Политика | Почему не Last-Write-Wins |
|---|---|---|
| Тексты карточки, описание, состав | объединение по полям; конфликт в одном поле — на ручное решение | две правки разных полей не должны затирать друг друга |
| **Цены** | конфликт **всегда** на ручное решение; в журнал | тихая перезапись цены — прямой финансовый ущерб |
| **Штрихкоды** | уникальность проверяется глобально; конфликт — ручное решение | один код на два товара ломает распознавание по штрихкоду |
| **Права доступа и пользователи** | изменения только от владельца; конфликт — отказ и уведомление владельца | LWW может вернуть отозванный доступ |
| Фото товаров | только добавление (файлы с хешем не меняются); архивирование — как изменение статуса | конфликтов почти нет |
| История распознаваний, журнал | только добавление, без конфликтов | — |
| Индекс | не синхронизируется, пересобирается | — |

## 4. Универсальная платформа и сеть магазинов (добавлено в 1.3)

Модель «узел магазина + необязательный центр организации» описана в документе 17. Для синхронизации это означает:

| Данные | Направление (в будущем) | Политика конфликтов |
|---|---|---|
| Каталог организации (товары, тексты, характеристики) | центр → узлы; правки в узлах — по правам | объединение по полям; конфликт в одном поле — на ручное решение |
| **Схема категорий и характеристик** | центр → узлы (общая схема); узел может добавлять свои характеристики, не меняя общих | изменение типа или удаление общей характеристики — только в центре и с предпросмотром последствий для всех магазинов |
| Ассортимент, цены, остатки магазина | принадлежат узлу; в центр — для отчётов | цены — **всегда ручное решение** при конфликте (как в §3) |
| История распознаваний | узел → центр, только обезличенная (D-10) и по решению владельца | только добавление |
| Журнал ИИ-помощника | остаётся в узле (по умолчанию) | — |
| Индексы | не синхронизируются, строятся на месте из каталога | — |
| Пользователи и права с областью «магазин» | управляются владельцем организации | изменения только от уполномоченных; конфликт — отказ и уведомление |

Задел в первой версии (UUID, `updated_at`, `version`, журнал, архивирование вместо удаления, `store_id` в истории и журнале) достаточен
для такой синхронизации. Таблиц очередей синхронизации и серверной части облака сейчас нет и не будет до отдельного решения.
