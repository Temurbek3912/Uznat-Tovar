# 01. Текущее состояние проекта

Анализ сделан по коду выпуска 2026-11-06. Каждая строка опирается на конкретный файл. Обозначения: ✅ реализовано · 🟡 частично · ⬜ нет.

## 1. Общая картина

| Параметр | Значение |
|---|---|
| Backend | Python 3.12, FastAPI, SQLAlchemy 2, pydantic-settings; около 10 тыс. строк в `app/`, `scripts/`, `ml/` |
| База | PostgreSQL 16 (Docker). Схему создаёт `scripts/bootstrap.py` через `create_all`; **Alembic в зависимостях, но миграций нет** |
| Очередь | Celery 5 + Redis 7 (брокер и хранилище результатов), воркер с `--concurrency=1` |
| ML | YOLO11n (Ultralytics), DINOv2-base (transformers), FAISS `IndexFlatIP` / NumPy, Tesseract (установлен в образе), собственный читатель штрихкодов |
| Frontend | Статические страницы без сборщика: `index`, `identify`, `products`, `settings`, `admin`, `preview`; словари ru/uz/en по 191 ключу |
| Запуск | Docker Compose: `db`, `redis`, `bootstrap`, `api`, `worker`. Образ CPU-only (`python:3.12-slim`), GPU в контейнере не используется |
| Тесты | 51 файл `tests/test_*.py`, около 685 тестовых функций (после уборки); 251 JS-проверка в 16 наборах |
| Контроль версий | **Нет** (на компьютере владельца проект не под git; изменения доставляются архивами и `apply_update.py`) |

## 3. Наследие старого аудита, которое остаётся в базе

Таблицы `shelves`, `planogram_slots`, `shelf_snapshots`, `detections`, `compliance_reports`, `cameras`, `camera_events`,
`agent_state` по-прежнему описаны в `app/db/models.py` и лежат в базе с данными. Приложение их не читает. Удалять их нельзя
без отдельного решения. Предложение — оставить и пометить в документации как «архив», схему не трогать (документ 14, R-09).

## 4. Сильные стороны, которые стоит сохранить

- Честность решений: нет «демо-порогов», заглушки только по явному флагу и с пометкой в ответе.
- Чистые модули без FastAPI и SQLAlchemy (`security.py`, `identify_service.py`, `catalog_upload.py`, `barcode.py`, `matcher.py`):
  логика тестируется без базы и GPU. Это хорошая основа для переноса в Desktop.
- Аккуратная обработка загрузок и путей, идемпотентный импорт каталога, проверка готовности воркера.
- Понятные сообщения для человека на русском.

## 5. Главные пробелы (по важности)

1. Нет проверки распознавания на реальных фото и нет эталонов на диске.
2. Нет анонимного доступа покупателя к распознаванию.
3. Нет миграций базы: расширять карточку, права и историю нельзя без базовой миграции.
4. Нет OCR упаковки, а он нужен для различения вариантов.
5. Нет владельца, гибких прав, журнала действий, временных паролей.
6. Резервная копия неполная (без фото и индекса), восстановление не проверяется.
7. Индекс без версии модели и без атомарной записи; удаление товаров не предусмотрено.
8. Нет узбекской кириллицы; данные товара одноязычные.
9. Нет контроля версий кода.
