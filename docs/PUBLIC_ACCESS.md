# Вход покупателя из интернета (QR без Wi-Fi магазина)

Покупатель сканирует QR-код магазина и открывает страницу «Узнать товар» **через свой мобильный интернет**: без Wi-Fi магазина,
без входа и без установки приложения. QR не меняется, пока магазин сам не сменит адрес.

**Через интернет открыта только страница покупателя.** Вход сотрудников, каталог, управление — недоступны (ответ «не найдено»),
даже если знать адрес. Программа держит для покупателей отдельный внутренний вход — `127.0.0.1:8100` (только на этом компьютере),
туннель подключается именно к нему. Сотрудники по-прежнему работают в сети магазина (порт 8000).

## Для владельца: проверка через Tailscale (бесплатно)

Подходит для проверок и демонстраций. **Для продажи магазинам не подходит:** бесплатный тариф Tailscale — только для
некоммерческого использования. Магазинам — Cloudflare со своим адресом (ниже).

1. Установите Tailscale: https://tailscale.com/download → войдите (можно через Google).
2. В файле `.env` в папке программы добавьте строку:

       PUBLIC_ACCESS=tailscale

   (или запускайте `start_demo.bat --public tailscale`).
3. Запустите программу как обычно. В окне появится:
   `Покупатели (из интернета, без Wi-Fi магазина) — этот адрес в QR-коде: https://<имя-компьютера>.<...>.ts.net/ui/shop.html`
   и QR-код.
4. **Первый раз** Tailscale может попросить включить Funnel: в окне будет строка «Туннель просит действие: https://login.tailscale.com/…».
   Откройте эту ссылку, включите **HTTPS** и **Funnel** (две кнопки) и дождитесь подтверждения — затем перезапустите программу.
   Первое открытие адреса после включения может занять около 20 секунд (Tailscale получает сертификат).
5. Проверка: на телефоне **выключите Wi-Fi**, отсканируйте QR — должна открыться страница покупателя.

Если что-то не так, программа всё равно запускается и работает в сети магазина, а в окне пишет, что исправить.

## Для программиста магазина: свой постоянный адрес

Каждый магазин — свой адрес, например `https://magazin1.example.com/`. Настраивается в `.env`, без участия разработчика программы.

| Настройка | Что значит |
|---|---|
| `PUBLIC_ACCESS` | `off` (по умолчанию) — только сеть магазина; `tailscale`; `cloudflare`; `manual` |
| `PUBLIC_BASE_URL` | постоянный адрес магазина: только `https://`, имя (не IP), без пути. Он идёт в QR |
| `CUSTOMER_PORT` | внутренний вход покупателя, по умолчанию `8100`; слушается только на `127.0.0.1` |
| `CLOUDFLARE_TUNNEL_TOKEN` | секрет туннеля Cloudflare (только для `cloudflare`) |

Неверная настройка (нет `https`, IP вместо имени, нет секрета, порт занят) не останавливает программу: вход из интернета просто
не включается, причина пишется в окне запуска.

### Вариант А. Cloudflare Tunnel (рекомендуется для магазинов; туннель бесплатный, нужен свой домен)

1. Домен магазина (или поддомен вашего домена) подключён к Cloudflare (бесплатный тариф).
2. Cloudflare Zero Trust → Networks → Tunnels → **Create a tunnel** (тип Cloudflared) → имя, например `magazin1`.
3. **Public Hostname**: `magazin1.example.com` → Service: `HTTP` `127.0.0.1:8100`.
4. Скопируйте токен туннеля (строка после `--token` в команде установки).
5. Установите `cloudflared` для Windows (https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/).
   Службу Windows `cloudflared service install` ставить **не нужно**: программа сама запускает туннель вместе с собой и
   останавливает вместе с собой.
6. В `.env`:

       PUBLIC_ACCESS=cloudflare
       PUBLIC_BASE_URL=https://magazin1.example.com/
       CLOUDFLARE_TUNNEL_TOKEN=<токен>

Токен передаётся `cloudflared` через переменную `TUNNEL_TOKEN`, не в командной строке (её видно в списке процессов).
Адрес покупателя для ограничения частоты берётся из заголовка `CF-Connecting-IP`.

### Вариант Б. Свой туннель или обратный прокси (`manual`)

Любой туннель или прокси (ngrok с постоянным доменом, frp, nginx/Caddy на сервере с белым IP и т. п.), который ведёт
`https://ваш-адрес/` на `http://127.0.0.1:8100`. Программа ничего не запускает, только кладёт адрес в QR:

    PUBLIC_ACCESS=manual
    PUBLIC_BASE_URL=https://magazin1.example.com/

Требования к прокси:
- вести **только на порт `CUSTOMER_PORT`** (8100), не на 8000: на 8000 — вход сотрудников;
- передавать адрес покупателя в `X-Forwarded-For` (или `CF-Connecting-IP` / `X-Real-IP`) — иначе ограничение
  «12 снимков в минуту с телефона» не работает по телефонам, остаётся только общий предел 60 в минуту на весь вход;
- допускать тело запроса до 10 МБ (фото товара);
- HTTPS — на стороне туннеля/прокси (внутренний вход работает по HTTP, снаружи компьютера он недоступен).

### Проверка после настройки

- с телефона без Wi-Fi: `https://ваш-адрес/` → открывается страница покупателя;
- `https://ваш-адрес/ui/admin.html` и `https://ваш-адрес/api/v1/auth/login` → «не найдено» (404);
- снимок товара → ответ «Найдено» / «нет в базе».

## Что учесть

- Работает, пока включены компьютер магазина и интернет в магазине. Пропал интернет — QR не открывается (сеть магазина работает).
- Страницу может открыть любой, у кого есть адрес, а не только тот, кто в магазине. Защита — ограничение частоты: 12 снимков
  в минуту с телефона, 60 в минуту на весь вход.
- Фото товара, как и раньше, не сохраняется (D-10а: только в памяти, до 2 минут). С Tailscale шифрование заканчивается на этом
  компьютере; с Cloudflare — на серверах Cloudflare (они передают фото дальше, но технически его видят).

## Как устроено (для разработчиков)

- `scripts/serve.py` — API на двух сокетах в одном процессе: основной (`--port`) и вход покупателя (`127.0.0.1:--customer-port`,
  без lifespan, без `proxy_headers`). Один процесс — модели облегчённого режима грузятся один раз.
- `app/core/customer_gate.py` — `CustomerGateMiddleware`: запрос на порт `CUSTOMER_PORT` (по `scope["server"]`, его клиент
  не подделает) — только страница покупателя и `/api/v1/public/*`; адрес покупателя из заголовка туннеля — только на этом сокете.
- `scripts/public_access.py` — что запустить: `tailscale funnel <порт>` (без `--bg`: выключается вместе с программой; адрес —
  `tailscale status --json`), `cloudflared tunnel --no-autoupdate run`, или ничего (`manual`).
- `scripts/start_demo.py` — `--public off|tailscale|cloudflare|manual` (сильнее `.env`); туннель — необязательная служба:
  его остановка не останавливает программу.
- Тесты: `tests/test_public_access.py` (в том числе настоящий сервер на двух портах).
