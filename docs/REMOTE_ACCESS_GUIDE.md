# Вход администраторов, второй фактор и VPN — инструкция для владельца

> **Состояние (2026-11-08).** По вашим решениям В-1…В-4 (VPN; второй фактор обязателен всем администраторам; сеанс не дольше
> 8 часов). Написано и проверено **только в облачной копии**. На вашем компьютере не запускалось; серверная часть ещё не
> выполнялась с настоящим FastAPI и базой данных. Включать на рабочей системе — после проверки в среде по `requirements.txt` и только
> с вашего разрешения. VPN никто не подключал. Устройство решения — `docs/architecture/18_REMOTE_ADMIN_ACCESS.md`.

## 1. Как это устроено

- **Два адреса одной программы:**
  - `https://АДРЕС-КОМПЬЮТЕРА:8000` — для сотрудников (сеть магазина). **Только по HTTPS** (п. 7): по обычному `http://` с телефона
    пароль не отправляется. Управление пользователями, магазинами, полками, камерами **и правка каталога** здесь не работают;
  - `http://localhost:8001` — административный: открывается **только на самом компьютере магазина** (и через VPN, п. 6).
    «Управление» — `http://localhost:8001/ui/admin.html`;
  - вход, выполненный на адресе для сотрудников, управления не даёт нигде — для управления войдите на административном адресе;
  - запуск без Docker (`start_demo`): управление — только на самом компьютере, `http://localhost:8000/ui/admin.html`.
- **Каждый администратор входит с паролем и 6 цифрами** из приложения на телефоне — везде, в том числе на компьютере магазина.
- Сеанс администратора — **не больше 8 часов** от входа. Потом — вход заново с кодом.
- Перед важными действиями (создать или изменить пользователя, сбросить второй фактор, удалить магазин или полку) программа
  может попросить **ещё раз пароль и код**, если вы их вводили больше 10 минут назад.
- «Настройки» → «Безопасность входа»: где выполнен вход (компьютер или телефон, когда), завершить любой сеанс, «Выйти на всех
  устройствах», коды восстановления.

## 2. Один раз при установке: ключ сервера

Без этого ключа второй фактор не настроить — **администраторы не смогут войти**.

1. `docker compose exec api python -m scripts.generate_secret_key --auth`
2. Напечатанную строку `AUTH_SECRET_KEY=…` добавьте в `.env` рядом с `docker-compose.yml`.
3. `docker compose up -d`
4. **Сохраните ключ отдельно** (менеджер паролей или флешка, не рядом с резервными копиями). Потеря ключа = всем заново
   настраивать второй фактор (п. 5, консоль).

## 3. Владелец системы

- Владелец — первый администратор, созданный командой `scripts.bootstrap` на компьютере магазина. Через программу владельцем
  стать нельзя.
- Только владелец может: дать кому-то роль администратора; сбросить второй фактор другому администратору. Остальные администраторы
  не могут ничего менять у владельца.
- Если владельца ещё нет (система ставилась до этого обновления) или его нужно передать:
  `docker compose exec api python -m scripts.user_admin owner --username ЛОГИН` (передать другому — добавить `--transfer`).

## 4. Первый вход администратора — настройка второго фактора

1. Установите на телефон приложение-аутентификатор: Google Authenticator, Microsoft Authenticator, Яндекс Ключ или другое.
2. **На компьютере магазина** откройте `http://localhost:8001/ui/settings.html`, войдите логином и паролем.
3. Программа предложит настроить второй фактор (на это есть 10 минут). Появится ключ из групп по 4 символа — в приложении
   «добавить по ключу» и введите его.
4. Введите 6 цифр из приложения → «Включить».
5. Программа покажет **10 кодов восстановления** — один раз. Запишите их на бумагу и храните отдельно от телефона.

Код «не подходит» — проверьте, что время на телефоне выставлено автоматически.

Сотрудникам второй фактор не обязателен; включить его можно там же, в «Настройках».

## 5. Потерян телефон

1. **Есть коды восстановления:** при входе введите код восстановления вместо 6 цифр. Каждый код действует один раз. Затем:
   - администратор просит владельца: «Управление» → пользователь → «Сбросить 2FA»; следующий вход — настройка заново (п. 4);
   - сотрудника сбрасывает любой администратор.
2. **Нет кодов, или телефон потерял владелец:** на компьютере магазина, в папке проекта:
   `docker compose exec api python -m scripts.user_admin reset-2fa --username ЛОГИН`
   Все сеансы пользователя завершатся; следующий вход — настройка заново (п. 4).
3. **Телефон украден** (или пароль мог узнать кто-то ещё) — сбросьте второй фактор **и пароль** сразу:
   `docker compose exec api python -m scripts.user_admin reset-2fa --username ЛОГИН --new-password`
   Иначе тот, кто знает пароль, может первым настроить второй фактор на свой телефон.
4. **Потерян ключ `AUTH_SECRET_KEY`:** создайте новый (п. 2), затем `reset-2fa` для каждого, у кого был второй фактор; все
   настраивают его заново.

## 6. Вход из дома через VPN (когда будете готовы)

Ничего из этого пока не сделано: VPN-сервис не выбирался, не покупался и не подключался.

1. Выберите VPN (WireGuard, Tailscale или подобный), установите на компьютер магазина и на телефоны/ноутбуки администраторов.
   У платных и сторонних сервисов проверьте условия — это ваше решение.

**Способ А — порт на адресе VPN** (подходит для любого VPN):
2. Узнайте адрес компьютера магазина **в VPN-сети** (например, `100.64.0.5` у Tailscale) и добавьте в `.env`:
   `VPN_BIND_IP=100.64.0.5`
3. Запуск — **двумя командами**: сначала вся программа как обычно, затем отдельно вход через VPN:
   `docker compose up -d`
   `docker compose -f docker-compose.yml -f docker-compose.vpn.yml up -d --no-deps admin-api-vpn`
   Не объединяйте их в одну (`… -f docker-compose.vpn.yml up -d` без `--no-deps admin-api-vpn`): если VPN в этот момент не
   подключён, Docker прервёт запуск и обычного административного входа `localhost:8001` (проверено 2026-11-21).
4. С устройства в VPN: `http://100.64.0.5:8001/ui/admin.html`. Канал шифрует VPN.
5. Если с телефона в VPN адрес не открывается, а на самом компьютере `http://100.64.0.5:8001` открывается — его закрывает
   брандмауэр Windows: разрешение для Docker Desktop обычно создано только для сетей «Общедоступная», а сеть VPN Windows считает
   «Частной». Разрешите порт 8001 **только на адаптере VPN** — в PowerShell от имени администратора (имя адаптера — как в
   «Сетевых подключениях», у Tailscale — `Tailscale`):
   `New-NetFirewallRule -DisplayName "Узнать товар: вход через VPN" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8001 -InterfaceAlias Tailscale`
   Это изменение настроек безопасности компьютера — делаете вы сами; убрать: `Remove-NetFirewallRule -DisplayName "Узнать товар: вход через VPN"`.

Если после перезагрузки VPN включился позже Docker, служба VPN-входа (`admin-api-vpn`) не запустится — это безопасно, вход на самом
компьютере продолжит работать. Подключите VPN и повторите вторую команду из шага 3.

Остановить всё вместе с VPN-входом: `docker compose -f docker-compose.yml -f docker-compose.vpn.yml down`. Простое
`docker compose down` VPN-вход **не останавливает**. Предупреждение `Found orphan containers (…admin-api-vpn…)` после
`docker compose up -d` означает то же самое и безопасно: VPN-вход продолжает работать.

**Способ Б — только для Tailscale: `tailscale serve`** (без привязки Docker к адресу VPN, с HTTPS):
1. На компьютере магазина: `tailscale serve --bg 8001` — Tailscale откроет `https://ИМЯ-КОМПЬЮТЕРА.….ts.net` только для устройств
   вашей сети Tailscale.
2. Добавьте это имя в `.env`: `ADMIN_ALLOWED_HOSTS=ИМЯ-КОМПЬЮТЕРА.….ts.net`, затем `docker compose up -d`.
3. **Никогда не включайте `tailscale funnel`** — он открывает доступ из интернета.

Если «Управление» пишет «Здесь управление недоступно», хотя вы на административном адресе, — программа не знает имя, по которому вы
зашли (защита от подмены адреса). Добавьте его в `ADMIN_ALLOWED_HOSTS` (через запятую) и перезапустите.

**Проверка после подключения** (с ваших устройств): с другого компьютера в Wi-Fi магазина адрес `http://АДРЕС-КОМПЬЮТЕРА:8001` не
должен открываться; с телефона в VPN — должен.

**Не пробрасывайте порты 8000 и 8001 на роутере в интернет.** Если позже понадобится свой домен и HTTPS — документ 18, §2,
вариант Б (отдельное решение).

Проверено 2026-11-21 на этом компьютере (Docker Desktop для Windows, адрес Tailscale, временная копия программы): способ А —
порт на адресе VPN работает рядом с `localhost:8001`, с адреса Wi-Fi порт 8001 не открывается, управление — только по адресу VPN.
Не проверено: вход с другого устройства через VPN (брандмауэр, п. 5 способа А), `tailscale serve`, автозапуск после перезагрузки
(документ 18, §12.2).

## 7. HTTPS для телефонов сотрудников (обязательно: пароли по Wi-Fi без защиты не передаются)

Ваше решение от 08.11: пароли, коды и токены — только по HTTPS или через VPN. Без этого шага сотрудники не смогут войти с телефонов.
Ничего не покупается и никуда не отправляется: программа создаёт **свой центр сертификатов магазина**, который годится только для
адресов вашей сети (даже если его ключ украдут, им нельзя подделать чужой сайт).

1. Узнайте адрес компьютера в Wi-Fi (например, `192.168.1.10`; в Windows — `ipconfig`, строка «IPv4-адрес»). Лучше закрепить его
   за компьютером в настройках роутера, иначе после смены адреса сертификат придётся выпускать заново.
2. `docker compose exec api python -m scripts.make_local_tls --ip 192.168.1.10 --name ИМЯ-КОМПЬЮТЕРА`
3. В `.env` добавьте `PUBLIC_HTTPS_URL=https://192.168.1.10:8000`
4. `docker compose -f docker-compose.yml -f docker-compose.https.yml up -d` (с VPN — затем, как в п. 6, отдельно
   `docker compose -f docker-compose.yml -f docker-compose.vpn.yml up -d --no-deps admin-api-vpn`).
5. **Установите центр магазина на каждый телефон** — файл `secrets/tls/ca.crt` из папки проекта (передайте его на телефон кабелем,
   через мессенджер самому себе или с флешки):
   - **Android:** «Настройки» → «Безопасность» → «Шифрование и учётные данные» → «Установить сертификат» → «Сертификат ЦС» → выбрать
     файл (название пунктов зависит от телефона);
   - **iPhone:** открыть файл → «Настройки» → «Профиль загружен» → «Установить»; затем «Основные» → «Об этом устройстве» →
     «Доверие сертификатам» → включить для «Uznat Tovar — store CA».
6. Откройте на телефоне `https://192.168.1.10:8000/ui/index.html`. Если браузер предупреждает о небезопасном соединении — **не
   продолжайте через предупреждение**: центр не установлен (шаг 5).

Через год (397 дней) сертификат сервера нужно продлить: `docker compose exec api python -m scripts.make_local_tls --ip 192.168.1.10
--renew` и перезапуск (шаг 4); центр на телефонах переустанавливать не нужно. Папку `secrets/` не отдавайте никому; файл `ca.key`
лучше хранить отдельно (флешка) и класть в папку только на время продления.

Временно (например, пока телефоны не настроены) правило можно выключить: `auth.require_secure_transport: false` в
`configs/config.yaml` — пароли снова пойдут по Wi-Fi открытым текстом; решение за вами.

## 8. Временные пароли сотрудников

- Новому сотруднику пароль выдаёт **программа**: временный, показывается один раз в окне после сохранения. Передайте его лично.
- Вход с временным паролем открывает только форму «придумайте свой пароль». Временный нельзя использовать после этого, и у него
  есть срок — 24 часа (настройка `auth.temp_password_hours`, вопрос Q-19 ещё открыт).
- Забыл пароль — «Управление» → «Пользователи» → «Временный пароль»: прежний пароль и все сеансы сотрудника сразу перестают
  действовать. Администраторам временный пароль выдаёт только владелец; если у администратора включён второй фактор, для смены
  временного пароля нужен и код из приложения.
- Пароль владельца из `.env` при первом запуске — тоже временный (без срока): при первом входе программа попросит придумать свой.
- С консоли: `user_admin reset-password --username ЛОГИН` задаёт временный пароль; `--permanent` — если пароль вводит сам владелец
  учётной записи.
