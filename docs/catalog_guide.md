# Каталог товаров: как снять эталоны и загрузить их пачкой

Система узнаёт товар, сравнивая его вид на полке с **эталонными фото** из каталога. Точность распознавания в магазине упирается
в качество каталога сильнее, чем в любую настройку. Хороший каталог — это не красивые рекламные картинки, а фото, похожие на то,
что увидит камера на полке.

## 0. Самый простой способ: страница «Товары» (без терминала)

Откройте **«Товары»** в меню (только администратор) → **«Добавить товар»**:

1. Напишите название — например, «Кола 0,5 л». Артикул система придумает сама.
2. Нажмите **«Снять или выбрать фото»** и снимите товар с 3–5 сторон (правила — в разделе 1 ниже). На телефоне откроется камера, на компьютере — выбор файлов.
3. Нажмите **«Добавить товар»**. Система изучает фото (от нескольких секунд до минуты) и сообщит «Готово».
4. Проверьте: **«Узнать товар»** → покажите товар камере — система должна назвать его.

Что ещё умеет страница: **«＋ Фото»** у товара — добавить ракурсов (так лечатся путаницы); **«Изменить»** — исправить название и цену (на узнавание не влияет);
если вы пишете название, которое уже есть, система предложит добавить фото к существующему товару, а не заводить второй.

### Штрих-коды

У товара может быть один или несколько штрих-кодов (форматы EAN-13, EAN-8, UPC-A). Привязать код можно четырьмя способами:
1. вписать в «Дополнительно» при добавлении товара;
2. **просто сфотографировать штрих-код на упаковке** и включить этот снимок среди фото — система прочтёт его сама и напишет «Найден штрих-код … — привязан к товару»;
3. «Изменить» у товара: добавить код или отвязать ошибочный (значок ×);
4. на странице «Узнать товар»: показали товар (система узнала его по виду) вместе со штрих-кодом на упаковке — появится кнопка **«Привязать этот штрих-код к «…»»**.

Как этим пользоваться: на странице **«Узнать товар»** поднесите штрих-код к камере близко и ровно — он должен занимать хотя бы треть ширины кадра и быть в фокусе. Если код привязан, товар назовётся сразу и точно (по коду, без модели распознавания), с ценой. Если код прочитан, но не привязан, система так и скажет и предложит «Добавить товар с этим штрих-кодом» (форма откроется с уже вписанным кодом).

Что важно знать: читаются только EAN-13, EAN-8 и UPC-A (логистические этикетки Code 128 и QR — нет); смазанный, мелкий или блестящий код может не прочитаться — тогда остаётся распознавание по виду. Каждый прочитанный код проверяется по контрольной цифре; опечатка при ручном вводе отклоняется с понятным объяснением. Один штрих-код может вести только на один товар.
**База данных:** для кодов создаётся новая таблица `product_barcodes` (автоматически при `docker compose up -d`; существующие таблицы и данные не меняются). Перед обновлением всё равно сделайте копию базы: `python scripts/backup_db.py`.

Для десятков товаров сразу удобнее папка `catalog/` и команда `scripts.import_catalog` — разделы 2–6 ниже. Оба способа работают вместе.

**Где лежат фото:** `data/catalog-uploads/<артикул>/` (сжатые до 1600 px, без данных GPS). Эту папку сохраняйте вместе с базой и `models/index/`.

**Если пересобираете индекс** (раздел 6): после импорта из папки выполните `python -m scripts.reindex_uploads --apply` — он доиндексирует фото, загруженные из браузера
(журнал `models/index/uploads_manifest.json` помнит, какие уже в индексе). Без этого такие товары потеряют векторы.

## 1. Как снимать эталоны

На каждый товар (SKU) — **5–8 фото**:

- **спереди** (главный вид) — 2–3 снимка: крупно и «как на полке» (с расстояния, с которого будет снимать камера);
- **под углом ±30°** слева и справа — на полке товар редко виден строго в лоб;
- при разном освещении (если возможно) — лампы магазина, а не студийный свет; без бликов на глянцевой упаковке;
- **упаковка целиком** в кадре, товар занимает большую часть кадра, без пальцев и посторонних предметов;
- **разные партии**: упаковка меняется (акции, редизайн) — снимите актуальную; старый дизайн добавляйте отдельными фото.

**Похожие товары** (один бренд, разные вкусы/объёмы/цвет крышки) — самое трудное: снимайте так, чтобы **отличие читалось** (вкус на
этикетке, объём, цвет). Именно эти пары система будет путать; отчёт после загрузки покажет, какие.

Технически: формат **JPG или PNG** (не HEIC с iPhone — сохраните как JPG), короткая сторона не меньше 224 px (лучше 600+), резкие. Фото с
телефона можно не поворачивать: поворот в метаданных (EXIF) учитывается.

Сколько это займёт: ориентировочно 2–4 минуты на товар с фото и переименованием; на 50 товаров — 2–3 часа. Это моя оценка, не замер.

## 2. Структура папки

```
catalog/
  products.csv              <- необязательно, но очень желательно
  COLA-0.5L/   1.jpg 2.jpg 3.jpg 4.jpg 5.jpg
  FANTA-0.5L/  1.jpg 2.jpg 3.jpg ...
  CHIPS-CLASSIC/ ...
```
Имя папки = артикул (SKU): буквы (в том числе русские), цифры и `. _ - +`, до 64 символов; без `\ / : * ? " < > |`. Артикулы,
отличающиеся только регистром, — разные товары в базе (инструмент предупредит). Скрытые папки (`.git`, `__MACOSX`) и подпапки внутри
папки артикула игнорируются; фото в корне каталога — тоже (с предупреждением).

`products.csv` — разделитель `,` или `;` (Excel в русской/узбекской локали сохраняет с `;`), заголовки русские или английские:

```
sku;name;brand;category;price
COLA-0.5L;Кола 0,5 л;BrandCola;Напитки;9900
FANTA-0.5L;Фанта 0,5 л;BrandCola;Напитки;9900
```
Обязательны `sku` (Артикул) и `name` (Название); `brand`, `category`, `price` — по желанию (по умолчанию «Не указан», «Без категории», цена не
задана). Цена: `99,90`, `1 200,50`, пусто — допустимы.

## 3. Проверка папки без базы и моделей

```powershell
python -m scripts.import_catalog --dir catalog --validate-only
```
Ничего не пишет, не требует базы и видеокарты: сканирует папку и проверяет каждое фото. **Ошибки** (блокируют): недопустимое имя
папки, ошибки в CSV, одно и то же фото в двух товарах. **Предупреждения**: мало фото у товара, фото размытое/мелкое/нечитаемое (оно
пропускается), точная копия фото внутри товара, HEIC, вложенные папки, фото лежат в корне, товар есть в CSV, но нет папки, и наоборот.

## 4. Загрузка

```powershell
python -m scripts.import_catalog --dir catalog
```
Покажет план (сколько товаров создать/дополнить), спросит подтверждение (`--yes` — без вопроса), посчитает эмбеддинги (первый запуск
скачивает модель DINOv2) и сохранит индекс и манифест. В конце — отчёт о каталоге (п. 5).

- **Повторный запуск безопасен.** Уже загруженные фото пропускаются (по хешу файла), новые фото к существующему товару **добавляются** — так
  вы докладываете эталоны для путаемых товаров. Дублей векторов нет.
- **Обрыв не портит данные.** Индекс и манифест сохраняются контрольными точками (`--checkpoint N`) и при Ctrl+C; сбойный товар не останавливает
  остальные и перечисляется в итоге — повторный запуск догрузит его.
- **Обновить названия/цены** из CSV у уже существующих товаров: `--update-metadata` (без флага инструмент только сообщит, что они отличаются).
- Необязательно: `--manifest ПУТЬ` (по умолчанию `models/index/import_manifest.json`), `--batch N` (фото за проход модели при нехватке памяти GPU), `--require-csv`.

## 5. Отчёт о каталоге — читайте его

После загрузки печатается самопроверка по загруженным эталонам: доля фото, чьё ближайшее *другое* фото принадлежит тому же товару, список
хуже всего отделяемых товаров и **пары похожих товаров** (сходство ≥ 0.90). Для пар из списка система будет сомневаться и отправлять рамки
в ручную проверку. Что делать: добавить этим товарам фото с различающими ракурсами и перезапустить импорт; позже включить правило запаса
`margin_threshold` (`docs/pilot_plan.md`). Это **предсказание по эталонам**, а не замена оценке на настоящих фото полок.

## 6. Заменить фото или пересобрать каталог

Индекс не умеет удалять векторы. Чтобы **заменить** плохие эталоны: поправьте папку, затем
**удалите** файлы индекса (`models/index/catalog.faiss` и `catalog.faiss.ids.json`) и манифесты (`models/index/import_manifest.json` и `uploads_manifest.json`) и запустите импорт снова:
товары уже в базе, фото из папки добавятся в чистый индекс. Затем `python -m scripts.reindex_uploads --apply` вернёт фото, загруженные из браузера.
**Осторожно:** товары, фото которых нет ни в папке `catalog/`, ни в `data/catalog-uploads/` (заведённые другим способом), потеряют векторы. Перед удалением
сделайте копию папки `models/index/`. **Остановите воркер** на время пересборки (`docker compose stop worker`, потом `docker compose start worker`). В рабочей копии
от 2026-11-07 воркер уже не перезаписывает индекс, записанный импортом (сравнение поколений файла), и сам перечитывает его,
но добавление товара во время импорта прервёт импорт на ближайшем сохранении. Рядом с индексом появляется пустой файл
`catalog.faiss.lock` (блокировка) — его можно не трогать; при полной пересборке удалять его не обязательно.

## 7. Ограничения (честно)

- Нельзя **удалить** товар или **убрать** отдельное фото через страницу: индекс не умеет удалять векторы, а на товар ссылаются схемы выкладки и результаты. Ошибочный товар лучше переименовать; плохое фото — пересобрать индекс (раздел 6).
- Распознавание на странице «Узнать товар» использует те же пороги `match_threshold`/`unknown_threshold`, что и разбор полки; пока они не подобраны на ваших настоящих фото (`docs/pilot_plan.md`), граница «уверенно / похоже / не знаю» ориентировочная.
- Товары, созданные не импортом (через API или `add_product_from_local_file`), в манифесте не числятся: их фото из папки добавятся при первом импорте, если
  артикул совпадает.
- Артикулы уникальны в базе с учётом регистра. Переименование артикула = новый товар.
- Индекс — файл в памяти воркера (один процесс — `--concurrency=1`); общий индекс для нескольких воркеров не реализован (`docs/HANDOFF.md`, №14).
- Эталоны, снятые не так, как видит камера в магазине (студия, рекламные картинки), дают заметно худшую точность; проверяйте на настоящих фото (`docs/pilot_plan.md`).

## Сверка индекса с базой и уборка (рабочая копия от 2026-11-07)

- `python -m scripts.reconcile_index` — отчёт: векторы товаров, которых нет в базе; товары без векторов; устаревшие отметки
  журнала. `--apply` — восстановление: сначала копия файлов в `models/index/backup-<время>/`, затем удаляются только векторы
  товаров, которых нет в базе; фото и товары не трогаются. Товарам без векторов: `python -m scripts.reindex_uploads --apply`.
- `python -m scripts.cleanup_temp` — показать временные файлы, оставленные оборванной записью; `--apply` — удалить (только
  временные файлы программы, с журналом в `logs/cleanup-temp.log`).
- `python -m ml.build_catalog_embeddings` — только опытный индекс в отдельный путь (`--output-index`), для сравнения моделей. Рабочий индекс он не пишет (с 2026-11-21): новые товары из папок с артикулами — `scripts.import_catalog`, пересборка рабочего индекса — `scripts.rebuild_index --apply`. Папки сопоставляются с товарами базы по id или артикулу; неизвестные — отказ до записи.
- Скрипты лучше запускать внутри контейнера (`docker compose run --rm api python -m scripts.…`), а не в Windows-Python на
  компьютере: блокировка индекса в Windows и в контейнерах друг друга не видит.
