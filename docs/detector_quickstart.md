# Детектор на своих фото: от съёмки полки до рабочих весов

Для демонстрации на реальной полке нужен детектор, обученный на **ваших** снимках. Готового детектора в проекте нет, а запасная
эвристика по контурам рассчитана только на очень простой макет (см. п. 9). Этот путь быстрее, чем обучение на SKU-110K
(`training_guide.md`): не нужно скачивать 13 ГБ, достаточно 40–80 фото и одного вечера.

> **Честно про результат.** Детектор, обученный на одной полке, хорошо работает на этой полке в похожих условиях и заметно хуже на
> чужой. Для курсовой это нормально: снимайте обучающие фото там же, тем же телефоном/камерой и при том же свете, что будут на защите.

Все команды запускаются из папки проекта: `python -m ml.detector_kit <команда>`. Ничего не нужно устанавливать сверх проекта,
кроме `ultralytics` (для обучения; `pip install -r requirements.txt` уже его ставит).

## 1. Съёмка (самое важное для качества)

- **40–80 фото** полки. Для одной и той же демо-полки можно и 20–30, но будет хуже на других ракурсах.
- Разнообразие вместо повторов: 2–3 расстояния, ракурс прямо и с небольшим углом (до ~20°), разный свет (лампы, окно), **разная
  раскладка** товаров (переставляйте). Подряд идущие почти одинаковые кадры почти ничего не добавляют, а в проверочную часть
  попадают «двойники» обучающих и завышают оценку.
- 5–10 фото **пустой полки/фона** без товаров — чтобы детектор не придумывал товары там, где их нет.
- Снимайте так, как будете демонстрировать: тем же телефоном (через страницу «Узнать товар») или камерой. Телефонные фото 12 Мп можно не
  уменьшать — детектор их сам масштабирует.
- Положите все фото в одну папку, например `photos/`.

## 2. Черновая разметка (экономит время)

Рисовать рамки вокруг каждой упаковки с нуля — самая долгая часть (30–60 рамок на фото). Сначала пусть детектор нарисует черновик:

```powershell
python -m ml.detector_kit preannotate --images photos --out photos
```
Рядом с каждым фото появится `имя.txt` (рамки в формате YOLO) и `classes.txt`. Если весов нет, рамки рисует грубая эвристика —
она будет много ошибаться, но на простых полках это всё равно быстрее, чем с нуля. **Существующая ручная разметка не затирается**
(флаг `--overwrite` — только если вы этого хотите).

## 3. Правка разметки в редакторе

Откройте папку с фото в редакторе разметки, режим **YOLO**, один класс `product`:

- **CVAT** (cvat.ai, бесплатно онлайн) или **Label Studio** — надёжные варианты;
- **Roboflow** — удобен, есть подсказки по авторазметке, но данные загружаются в облако;
- **LabelImg** — работает офлайн с `classes.txt`, но давно не обновляется и на новых версиях Python может не ставиться.

Правила: рамка вокруг **каждой видимой упаковки лицевой стороной**; частично закрытые, если видна большая часть, — размечать видимую
часть; одинаковые правила на всех фото. Удалите лишние рамки черновика, добавьте пропущенные. Экспортируйте в формат **YOLO** так,
чтобы `.txt` лежали рядом с фото (или в отдельной папке `labels/` — тогда укажите её в `--labels`).

**Ускоритель (цикл):** разметили 15–20 фото -> обучили (шаги 4–5) -> `preannotate` остальных уже обученными весами
(`--weights models/detector/sku110k_yolo11n.pt`) -> поправили -> обучили заново. С каждым кругом правок меньше.

## 4. Разбиение и проверка датасета

```powershell
python -m ml.detector_kit split --src photos --dst dataset          # 80% train / 20% val, создаёт dataset/data.yaml
python -m ml.detector_kit check --dataset dataset                    # формат, рамки, размер — ДО обучения
```
`check` ловит типичные ошибки: рамки в пикселях вместо нормированных координат (0–1), формат с полигонами, повреждённые фото,
пустую проверочную часть, слишком мелкие объекты, фото без разметки (они считаются «фоном» — если вы просто забыли разметить, детектор
научится игнорировать товары). Исходные файлы `split` не меняет и не перезаписывает непустую папку.

## 5. Обучение

```powershell
python -m ml.detector_kit train --data dataset/data.yaml
```
Что происходит: проверка датасета -> дообучение готовой модели `yolov8s.pt` (при первом запуске скачивается из интернета) -> лучшие
веса копируются в `models/detector/sku110k_yolo11n.pt` — туда, откуда их берёт проект; прежние веса сохраняются рядом как `.bak`.

- **Сколько займёт:** на RTX 5060 с 8 ГБ при ~60 фото ориентировочно 15–40 минут (это оценка, я не измерял на вашей машине).
  На процессоре — часы, поэтому перед обучением проверьте видеокарту: `python -m scripts.preflight` (нужен PyTorch с `cu128`).
- Не хватает памяти видеокарты: `--batch 4 --imgsz 960`. Мало фото и быстро переобучается: `--epochs 50`.

## 6. Оценка: годится ли детектор

```powershell
python -m ml.detector_kit evaluate --images dataset/images/val --labels dataset/labels/val --out eval
```
Печатает точность, полноту и F1 (рамка засчитывается, если пересекается с размеченной по IoU ≥ 0.5) и **советы простыми словами**.
В папке `eval` — картинки: **зелёная** рамка — товар найден, **красная** — лишняя рамка детектора, **синяя** — товар, который детектор
пропустил. Откройте их — так сразу видно, что именно не получается.

| F1 | Вердикт |
|---|---|
| ≥ 85% | хорошо для демонстрации на этой полке |
| 60–85% | средне: добавьте фото и разметку, обучите заново |
| < 60% | для демонстрации не годится |

Оценка идёт по проверочным фото (`val`) — детектор их не видел при обучении. Если проверочных фото мало (3–5), цифра шумная.

## 7. Подключение к проекту

Ничего настраивать не нужно: воркер читает `models/detector/sku110k_yolo11n.pt` **при старте**. Перезапустите демонстрацию
(`start_demo.bat` / `python -m scripts.start_demo`) — и новый детектор работает. Если путь другой — `models.detector.weights_path`
в `configs/config.yaml`.

## 8. Детектор — это половина дела: каталог товаров

Детектор находит *где* лежит упаковка, а *какой это товар* определяет эмбеддер DINOv2 по каталогу. Для каждого товара
нужно 3–5 фото (с разных сторон и при разном свете): `python -m scripts.add_product_from_local_file ...` (RUNBOOK, п. 6.3).
Без каталога «Узнать товар» честно ответит «каталог пуст» или «товар не найден» — это не ошибка детектора.

## 9. Если совсем нет времени: макет + эвристика

Запасной детектор без обучения замерен на синтетических полках (цветные коробки на светлом фоне, 3 яруса по 6, IoU 0.5):

| Сцена | F1 |
|---|---|
| зазоры между коробками ~14 px, однотонные | ≈ 75% |
| зазоры ~3 px | ≈ 79% |
| с рисунком на упаковке и шумом фото | ≈ 70% |
| **вплотную, без зазоров** | **≈ 32%** |

Предыдущая версия эвристики склеивала весь ярус в одну рамку и давала **0%** даже здесь. Принципиальный предел: товар без видимой
границы с доской полки (тёмный на тёмном) сливается с ней и соседями; на реальных упаковках с мелким текстом много лишних рамок.
**На реальных фото не рассчитывайте на неё** — используйте её для черновой разметки (шаг 2) или для очень простого макета.

## Если что-то не получается

| Симптом | Что делать |
|---|---|
| `check`: «значения должны быть от 0 до 1» | редактор экспортировал пиксели — экспортируйте в формат YOLO (нормированные), не Pascal VOC |
| `check`: «формат с полигонами» | выбран экспорт сегментации — нужен именно детекция (рамки) |
| `evaluate`: «нет ни одной пары фото + разметка» | неверные папки `--images`/`--labels` или имена файлов не совпадают (`a.jpg` ↔ `a.txt`) |
| рамки в 5–10 раз больше товаров | детектор склеивает соседей: типично для эвристики — обучите YOLO |
| много красных (лишних) рамок | добавьте фото пустой полки, проверьте, что размечены ВСЕ товары на обучающих фото |
| много синих (пропущенных) | больше фото с разных ракурсов/света, дольше обучение |
| обучение «Out of memory» | `--batch 4 --imgsz 960` |
