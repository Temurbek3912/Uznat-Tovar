## 3. Что я оспариваю в решениях и почему

1. **«Два клика» и Docker несовместимы.** Docker Desktop требует виртуализации и заметной доли памяти; на слабом ноутбуке и у продавца без техподдержки это не «два клика».
   Предлагаю **локальный режим**: один процесс, база SQLite, очередь внутри программы, без Redis, Celery и Docker. Docker остаётся для серверной установки.
   Что проверено по коду: тесты проекта уже работают на SQLite; специфики PostgreSQL в моделях не нашёл, кроме поиска `ILIKE`; очередь спрятана за одной функцией `_enqueue` в `routes_catalog.py`.
   Риск: в SQLite поиск `LIKE` не игнорирует регистр для кириллицы (запрос «мышь» не найдёт «Мышь») — нужен свой поиск без учёта регистра (учтено в этапе E).
2. **Телефон «как приложение» требует HTTPS.** По адресу вида `http://192.168…` браузер не даёт ни живую камеру, ни установку на экран. Запасной путь уже есть в коде: кнопка «Сделать фото» открывает камеру телефона и работает без HTTPS.
   Предлагаю: сначала сайт + «Сделать фото» (работает сразу), установку как приложение включаем, когда у вас будет HTTPS (варианты разберём на этапе G, выбор за вами).
3. **Красивый голос на трёх языках нельзя «в лоб» на слабом ПК.** Узбекский: Navoiy требует видеокарту NVIDIA, CUDA и Linux/WSL2 (по описанию авторов; RTX 5060 не проверена); у Meta MMS узбекский только кириллицей и лицензия некоммерческая — для продукта не годится;
   Anadil (MIT) пока не изучен. Поэтому **озвучка записывается заранее**: фразы интерфейса и названия товаров один раз на вашем мощном ноутбуке, хранятся файлами, слабый ПК только проигрывает.
   Это то же решение, что вы приняли 2026-10-23 (пункт 6), теперь оно становится частью программы. Запасной вариант — голоса Windows (`voice.js` уже выбирает лучший и молчит, если голоса языка нет).
4. **«Мировой уровень» нельзя проверить одними тестами.** У меня есть настоящий Chromium: экраны я снимаю и смотрю сам (`tools/ui_screenshots/preview_shots.py`), плюс автоматические проверки (контраст, размеры кнопок, фокус, адаптивность).
   Но шрифты и экраны ваших устройств у меня другие (например, нет Segoe UI), поэтому финальный взгляд на реальном ноутбуке и телефоне остаётся за вами: откройте витрину и пришлите снимок или замечания.
5. **Не всё сразу.** Порядок ниже выбран так, чтобы после каждого шага программа работала и проверялась: безопасность → уборка → экран «Узнать товар» → локальный режим → установщик → телефон → озвучка → скорость.
6. **Установщик Windows я собрать у себя не могу:** сборка делается на Windows. Я подготовлю все файлы и одну команду, вы её запустите и пришлёте результат.
7. **Размер программы.** Сейчас в зависимостях torch, transformers, faiss, ultralytics (последний нужен только для полок и уйдёт при уборке). Цель — сократить установку; решим по результатам `bench` (например, перевод модели в более лёгкий формат — только если точность узнавания не упадёт, это проверяется отдельно).

## 5. Дизайн: как работаем (этап D)

- Тема: инструмент для продавца и покупателя в магазине компьютерной техники (Узбекистан); телефон и ноутбук; нередко плохой свет и шум. Главное действие: показал товар — сразу увидел название, главные характеристики и цену.
- Главный экран — камера: большое окно съёмки, ответ выезжает карточкой («паспорт устройства»: модель крупно, характеристики таблицей, цена), озвучка одной кнопкой. Остальное — тихое и без украшений.
- Концепция написана (`DESIGN_CONCEPT.md`): жёлтая «метка» ценника на графите, камера как тёмный видоискатель, системный шрифт. Нужно согласие пользователя; потом код. Значки — свои векторные (эмодзи выглядят по-разному на каждом устройстве). Шрифт должен уметь кириллицу и узбекскую `ʻ` (U+02BB); проверю до выбора.
- Автоматически проверяем: контраст пар цветов, размер кнопок, подписи и фокус, поведение на узком и широком экране. Глазами — по снимкам Chromium (мои) и по витрине на вашем устройстве (ваши).
