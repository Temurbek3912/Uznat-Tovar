# Локальное обучение детектора на SKU-110K

> **Для курсовой быстрее:** если у вас есть доступ к полке для съёмки, обучение на 40–80 собственных фото занимает вечер и даёт
> лучшее качество на вашей полке, чем SKU-110K, — см. [detector_quickstart.md](detector_quickstart.md). Этот документ — про большой датасет SKU-110K.

### Под ваше железо: Acer Predator Helios Neo 16S AI (Ultra 9 275HX / 32GB / RTX 5060 8GB)

Эта инструкция — отдельный процесс от Docker-стека проекта (`docker-compose.yml`, `Dockerfile`).
Здесь вы обучаете веса YOLO **локально на Windows**, а в проект (`retail-shelf-audit/`)
потом переносите только готовый файл `best.pt`. Тренировочное окружение и продовое
окружение проекта не обязаны совпадать.

## 2. Шаг 1 — обновить драйвер NVIDIA

Blackwell (RTX 50-серия) требует свежий драйвер. Зайдите на официальную страницу драйверов
NVIDIA, укажите модель "GeForce RTX 5060 Laptop GPU", скачайте последнюю версию (Game Ready
или Studio — для обучения моделей разницы нет) и установите. После установки проверьте в
командной строке (PowerShell или CMD):

```powershell
nvidia-smi
```

В выводе должна быть строка с версией CUDA **12.8 или выше** и модель GPU. Если версия ниже —
драйвер всё равно старый, обновите ещё раз.

## 3. Шаг 2 — Python и отдельное окружение для обучения

## 4. Шаг 3 — PyTorch с поддержкой RTX 5060 (Blackwell)

Это самый рискованный шаг — если ошибиться здесь, обучение будет либо не запускаться, либо
молча идти на CPU (в 10-20 раз медленнее) без явной ошибки.

**Сначала попробуйте официальную стабильную сборку:**

```powershell
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
```

**Обязательно проверьте, что GPU реально используется**, прежде чем качать датасет:

```powershell
python -c "import torch; print('torch:', torch.__version__); print('CUDA available:', torch.cuda.is_available()); print('device:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'N/A'); x=torch.rand(1000,1000).cuda(); y=x@x; print('matmul OK:', y.shape)"
```

Ожидаемый результат: `CUDA available: True`, имя вашей видеокарты, `matmul OK`.

**Если увидели ошибку вида** `CUDA error: no kernel image is available for execution on the device`
**или** `sm_120 is not compatible` — стабильная сборка на вашей системе пока не подхватывает
Blackwell. Откат на более свежую preview-сборку:

```powershell
pip uninstall torch torchvision torchaudio -y
pip install --pre torch torchvision torchaudio --index-url https://download.pytorch.org/whl/nightly/cu128
```

Повторите проверочный скрипт выше. Если и это не помогает — на некоторых системах RTX 50-серии
надёжнее работает через WSL2 (Ubuntu) с тем же индексом cu128/nightly; это отдельная настройка
(включение WSL2, установка Ubuntu из Microsoft Store, драйвер CUDA внутри WSL2 не нужен —
используется драйвер Windows). Дайте знать, если понадобится — распишу отдельно, чтобы не
перегружать этот документ.

Актуальная команда установки может со временем измениться — если что-то не сходится,
сверьтесь с https://pytorch.org/get-started/locally/ (там официальный селектор под вашу CUDA).

## 6. Шаг 5 — скачивание SKU-110K

Самый простой путь — auto-download через Ultralytics прямо при первом запуске обучения
(следующий шаг скачает датасет автоматически при первом вызове `yolo train`). Учтите:
- 13.6 ГБ по нестабильному Wi-Fi может обрываться — по возможности используйте проводное
  подключение или Ethernet-адаптер на этот один раз.
- Скачивание идёт в `C:\yolo-training\datasets\SKU-110K` (относительно того, откуда запущена команда).

Альтернатива — скачать вручную с оригинального источника (со страницы датасета,
http://trax-geometry.s3.amazonaws.com/cvpr_challenge/SKU110K_fixed.tar.gz), но тогда разметку
придётся самостоятельно конвертировать в формат YOLO (csv → txt). Автозагрузка через Ultralytics
делает это сама — рекомендую её, если не нужен именно нетронутый оригинальный архив.

## 7. Шаг 6 — запуск обучения (параметры подобраны под 8 ГБ VRAM)

Сначала короткий тестовый прогон — проверить, что всё работает и увидеть реальное время на
эпоху ПЕРЕД тем, как запускать полное обучение на много часов:

```powershell
yolo train data=SKU-110K.yaml model=yolov8s.pt epochs=2 imgsz=960 batch=8 device=0 workers=8 project=runs name=sku110k_test
```

Почему такие параметры именно для вашей RTX 5060 8 ГБ:
- **`model=yolov8s.pt`** — не `yolov8m`/`yolov8l`: на 8 ГБ VRAM с большим imgsz средняя/крупная
  модель либо не влезет, либо заставит держать batch=1-2, что резко замедлит и ухудшит обучение.
  `yolov8s` — разумный баланс для этой задачи и этого объёма VRAM.
- **`imgsz=960`** — SKU-110K очень плотный (≈147 объектов на фото), маленькое разрешение (640)
  будет терять мелкие объекты. 960 — компромисс между качеством и VRAM; если поймаете
  `CUDA out of memory`, снижайте до 640 или уменьшайте batch.
- **`batch=8`** — стартовое значение. Можете заменить на `batch=-1` — Ultralytics сам подберёт
  максимальный batch под свободную VRAM (AutoBatch), это надёжнее ручного подбора.
- **`workers=8`** — ваш CPU это легко выдержит, не будет узким местом на подготовке данных.
- **`device=0`** — первая (и единственная) GPU в системе.

После тестового прогона посмотрите в консоли время на эпоху и умножьте на нужное число эпох,
чтобы понять реальный бюджет времени — не полагайтесь на цифры "из интернета" для другого
железа, у вас может отличаться в 2-3 раза в любую сторону.

**Полное обучение** (когда тестовый прогон отработал без ошибок):

```powershell
yolo train data=SKU-110K.yaml model=yolov8s.pt epochs=100 imgsz=960 batch=-1 device=0 workers=8 patience=15 project=runs name=sku110k_full
```

`patience=15` — остановка, если 15 эпох подряд нет улучшения (early stopping), чтобы не сжигать
время впустую на плато. Обучение можно прервать (Ctrl+C) и продолжить позже флагом `resume=True`
с тем же `name=`.

**Реалистичные ожидания по времени**: на 8 ГБ мобильной видеокарте полный прогон в 100 эпох на
8219 тренировочных изображениях — это, скорее всего, задача на многие часы, а не на "пока пьёте
кофе". Ориентируйтесь на цифру из вашего собственного тестового прогона (шаг выше), а не на
предположения — эта конкретная связка (RTX 5060 8ГБ + этот датасет) слишком нова, чтобы у меня
были надёжные проверенные benchmarks под неё.

**Если что-то идёт не так локально** — у Kaggle Notebooks бесплатная квота ~30 GPU-часов в
неделю (T4/P100, 16 ГБ VRAM — больше, чем у вас), и туда же можно подключить датасет прямо в
ноутбуке без скачивания на свою машину. Учитывая, что вы уже смотрели в сторону Kaggle — это
реальный fallback-план, если Blackwell-совместимость доставит проблем.

## 9. Шаг 8 — подключить веса к проекту

Скопируйте обученный файл в проект:

```powershell
copy runs\sku110k_full\weights\best.pt <путь_к_проекту>\retail-shelf-audit\models\detector\sku110k_yolo11n.pt
```

(Имя файла задано в `configs/config.yaml` (`models.detector.weights_path`) — сейчас `sku110k_yolo11n.pt`, то есть YOLO11n, обученная на SKU-110K. Если вы обучили другую архитектуру, сохраните веса под этим же именем либо поправьте `weights_path`: воркер читает ровно тот файл, который указан в конфиге, и больше никакой другой детектор молча не подставляется.)

Быстрая проверка, что веса грузятся классом из проекта:

```python
from app.pipeline.detector import YoloShelfDetector
detector = YoloShelfDetector(weights_path="models/detector/sku110k_yolo11n.pt", confidence_threshold=0.35)
print("Загрузилось без ошибок")
```
