# Узнать товар

Приложение для распознавания отдельных товаров по фотографии. Пользователь показывает товар камере или загружает фото, система
ищет его в каталоге и показывает карточку найденного товара. Если товара в каталоге нет, она честно говорит «не найден»; если
уверенности мало, говорит «не удалось определить уверенно», а не выдаёт похожий товар за найденный.

Интерфейс на русском, узбекском и английском. Работает локально: FastAPI, PostgreSQL, Redis, Celery, Docker.

> Раньше проект назывался Retail Shelf Audit (аудит торговых полок). Эта функциональность убрана вместе с кодом: магазины, полки,
> планограммы, OSA, отчёты, ручная проверка, камеры и агент, OCR ценников. **Данные прежнего аудита в базе PostgreSQL сохранены**
> (таблицы не удалялись), приложение их больше не использует. Что сделано и что осталось — `docs/CLEANUP_STATUS.md`.

## Что умеет сейчас и чего ещё нет

Умеет:

- каталог товаров: создание, правка, поиск, несколько фотографий одного товара, штрихкоды EAN-13, EAN-8 и UPC-A;
- распознавание по фото: вектор признаков DINOv2 → поиск похожих в индексе FAISS → решение `matched` / `uncertain` / `unknown`
  (и `empty_catalog`, если каталог пуст); штрихкод на кадре читается раньше и даёт точный ответ;
- вход по логину, роли, ограничение подбора пароля; фоновая обработка через Celery и Redis.

Ещё нет (запланировано, см. `docs/PLAN_V2.md`):

- цепочки «YOLO → вырезка товара → DINOv2 → FAISS» и выбора товара, если их несколько в кадре. Сейчас на странице «Узнать товар»
  признаки считаются по **целому кадру**, детектор YOLO в распознавании не участвует;
- проверки качества на реальных фотографиях: пороги `match_threshold` и `unknown_threshold` не откалиброваны. Быстрый взгляд на то,
  видит ли обученный YOLO товар на ваших фото: `python -m ml.probe_detector --photos data/probe --out data/probe_out`.

## Структура проекта

```
app/
  api/        маршруты: вход и пользователи, каталог, админ-панель, магазины (наследие, будет убрано)
  services/   каталог (создание, загрузка фото, импорт), распознавание, штрихкоды, вход
  pipeline/   детектор YOLO, эмбеддер DINOv2, поиск FAISS, запуск моделей, размытие лиц
  core/       настройки, безопасность, схемы, готовность системы
  db/         модели и подключение к базе
  worker.py   фоновые задачи: добавить товар, добавить фото, узнать товар
frontend/     страницы: главная, «Узнать товар», «Товары», «Настройки», админ-панель; переводы RU / UZ / EN
scripts/      запуск и обслуживание: bootstrap, preflight, импорт каталога, пользователи, резервная копия, самопроверка
ml/           оценка поиска, набор для обучения детектора, измерение детектора на ваших фото (probe_detector)
tests/        проверки Python;  tools/ — проверки интерфейса на JS и вспомогательные инструменты
configs/      config.yaml (пороги, пути к моделям);  docs/ — документация;  docker-compose.yml, Dockerfile
```

## Авторизация и роли (F13)

Весь API, кроме `GET /health` и `POST /api/v1/auth/login`, требует токен
(`Authorization: Bearer <токен>`). Доступ определяется двумя независимыми
вещами: **правом роли** и **скоупом магазинов**.

| Роль | Что может | Какие магазины видит |
|---|---|---|
| `merchandiser` | узнавать товары, смотреть каталог | только назначенные |
| `regional_manager` | узнавать товары, смотреть каталог | только назначенные |
| `analyst` | узнавать товары, смотреть каталог (только чтение) | вся сеть |
| `admin` | всё: каталог, пользователи | вся сеть |

> Привязка пользователей к магазинам и роли «по магазинам» — наследие аудита полок: «Узнать товар» магазины не нужны.
> Их планируется убрать отдельным выпуском (см. `docs/CLEANUP_STATUS.md`, «Этап Б»); пока они работают, как описано.

Подбор пароля ограничен: после 5 неудачных попыток входа на один логин (или 20 с одного
IP) за 15 минут `POST /auth/login` отвечает `429` с `Retry-After` — даже на верный пароль,
пока блокировка не снимется (параметры — секция `auth` в `configs/config.yaml`).

Чужой магазин: `403` на эндпоинтах с `store_id` в пути. Токены непрозрачные (не JWT),
в БД хранится только SHA-256 хеш; срок жизни — `auth.token_ttl_minutes` в
`configs/config.yaml` (по умолчанию 12 ч). Logout, смена пароля и
деактивация пользователя отзывают токены мгновенно.

```bash
python -m scripts.create_user --username admin --role admin    # первый админ (пароль спросит)
curl -X POST http://localhost:8000/api/v1/auth/login -d "username=admin&password=<пароль>"
curl -H "Authorization: Bearer <токен>" http://localhost:8000/api/v1/auth/me
```
**Перед выходом за пределы localhost** (подробности — `docs/HANDOFF.md`, раздел «F13»):
терминируйте HTTPS на reverse-proxy; запускайте `uvicorn --proxy-headers --forwarded-allow-ips=<IP прокси>`,
иначе лимит входа по IP будет считать всех пользователей одним адресом; счётчик попыток
живёт в памяти одного процесса (для нескольких воркеров нужен общий, например в Redis);
задайте `CORS_ALLOW_ORIGINS` списком адресов (без неё в `ENVIRONMENT=production` кросс-доменный доступ закрыт, в `development` открыт для всех; см. `.env.example`).

Остальных пользователей админ создаёт через `POST /api/v1/users` (Swagger UI
на `/docs` умеет логиниться кнопкой Authorize). Реализация: чистая логика —
`app/core/security.py` (тесты `tests/test_security.py`), БД — `app/services/auth_service.py`,
HTTP — `app/api/deps.py` + `app/api/routes_auth.py`. Ограничения и что не
сделано — в `docs/HANDOFF.md`.

## Запуск через Docker (рекомендуется)

Всё — Postgres, Redis, API, Celery-воркер, зависимости Python и Tesseract — живёт в Docker; ставить на компьютер ничего,
кроме Docker Desktop, не нужно. С чистой машины:

```powershell
git clone <адрес-репозитория>
cd retail-shelf-audit
copy .env.example .env          # необязательно; см. ниже про первого администратора
docker compose build            # первый раз долго: torch и др. — несколько ГБ
docker compose up -d
```

`docker compose up -d` сам подготовит систему: дождётся Postgres, **создаст таблицы и папки** (`data/`, `models/`, `logs/`),
создаст **первого администратора** и только потом запустит `api` и `worker` (сервис `bootstrap`, см. `scripts/bootstrap.py`).

**Первый администратор** — один из двух способов:

1. задать `ADMIN_USERNAME` и `ADMIN_PASSWORD` в `.env` до `docker compose up -d` — создастся сам;
2. иначе выполнить `docker compose run --rm bootstrap` — он спросит логин и пароль.

Пароль по умолчанию не существует намеренно: система открыта в локальную сеть (телефон снимает по Wi-Fi).

**Первый товар** — в браузере: `http://localhost:8000` → вход → «Товары» (`/ui/products.html`): название и 3–5 фото. Магазины и полки
не нужны, демо-данные не создаются.

| Нужно | Команда |
|---|---|
| Обычный запуск / после перезагрузки | `docker compose up -d` (контейнеры сами стартуют вместе с Docker Desktop) |
| Остановить, **данные сохранить** | `docker compose down` |
| Проверить, что всё работает | `docker compose ps` (db, redis, api, worker — `healthy`), затем `docker compose exec api python -m scripts.smoke_test` |
| Логи | `docker compose logs -f api` / `worker` / `db` / `bootstrap` |
| Применить правку `.env` | `docker compose up -d` |
| Применить правку кода | `docker compose restart api worker` (код примонтирован, пересборка не нужна) |
| Правка `requirements.txt` или `Dockerfile` | `docker compose build` и `docker compose up -d` |

**Главная:** `http://localhost:8000/` (откроется `/ui/index.html`) — кнопки «Узнать товар», «Товары», «Управление»; кнопки видны по роли пользователя, а на новой установке главная сама подсказывает первые шаги (добавить товары). Интерфейс одинаково удобен на ноутбуке (меню слева) и на телефоне (нижняя панель). Проверки интерфейса без браузера: `python tools/run_js_tests.py` (нужен Node.js).

**Админ-панель:** `http://localhost:8000/ui/admin.html` (товары, пользователи, система). Распознавание — `/ui/identify.html`, API — `/docs`.
Диагностика БД — `docker compose exec api python -m scripts.diagnose`; бэкап — `python scripts\backup_db.py`.

**Не используйте `docker compose down -v`**: флаг `-v` удаляет тома, то есть всю базу данных.
Подробности, бэкап БД, разбор типичных ошибок и список того, что пока делается командами, — в [`docs/DOCKER.md`](docs/DOCKER.md).

## Быстрый старт (разработка на хосте, без Docker-образа)

Postgres и Redis — из Docker (`docker compose up -d db redis`), а API и воркер — в локальном venv; так на Windows
напрямую доступна GPU. Для обычной работы используйте раздел выше.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
docker compose up -d db redis
cp .env.example .env

python -m scripts.create_user --username admin --role admin   # первый администратор (F13)
uvicorn app.main:app --reload         # API на http://localhost:8000
pytest tests/ -v                      # все unit-тесты

# test_privacy.py не требует pydantic/torch/faiss — можно гонять отдельно даже до полной установки requirements.txt:
pytest tests/test_privacy.py -v
```

## Что проверено и что нет

- Не запускалось целиком вместе с настоящими FastAPI, Celery, PostgreSQL и Docker в среде разработки (она без сети). Проверено
  без них: синтаксис всех файлов, статический разбор импортов, чистая логика, проверки интерфейса на JS (`python tools/run_js_tests.py`).
  Перед использованием выполните `docker compose up -d` целиком и `docker compose run --rm --no-deps api python -m pytest -q`.
- **Качество распознавания на реальных фотографиях не измерено.** Не рассчитывайте на точность без собственного набора фото.
- `FaceBlurrer` на каскаде Хаара хорошо ловит лица анфас при нормальном свете; для профилей рекомендуется DNN-детектор.
- `CatalogService.add_product` сохраняет индекс на диск при каждом добавлении товара: для загрузки тысяч товаров используйте
  `add_product(..., persist=False)` в цикле и один `save_index()` в конце.
- `HeuristicContourDetector` и `RandomDebugEmbedder` — только для тестов и демо. Воркер включает их лишь явно
  (`ALLOW_HEURISTIC_DETECTOR=1`, `ALLOW_DEBUG_EMBEDDER=1`); результаты с ними ненадёжны.

## Лицензии моделей

При выборе конкретных pretrained-весов (YOLO, DINOv2/CLIP) проверьте лицензию
каждой модели на предмет допустимости коммерческого использования — это
зависит от конкретного чекпоинта и может измениться со временем.
